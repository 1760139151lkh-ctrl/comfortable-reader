# 数学排版：从首次输入到可读公式

## 判定顺序

1. **先确定原稿是什么**：文字 LaTeX 是源文本；PDF 公式图是视觉源，OCR 只是候选。
2. **再确定结构**：上下标属于谁、根号盖住哪里、括号种类、横线含义、分段条件、表头与标签位置。
3. **然后编译**：用 `scripts/math_rendering.py` 或经过验证的等价路径生成 MathML。
4. **检查 XML 和可见命令残留**：编译函数没有抛异常也可能输出字面的 `\command`。
5. **最后对照原稿看结果**：逐项核对符号和实际呈现；编译成功不能使错误转写变正确。

LaTeX 是排版源文本；MathML 是表达变量、运算、上下标、分数、根号和表格等关系的结构。两者都可能合法但表达错内容。不要用“已经 MathML 化”代替语义检查。

## 每个公式至少检查什么

| 必查项 | 已发生过的错误类型 |
|---|---|
| 字母身份与大小写 | `a_n` 误代 `α_n`；大写 O 误成小写 o；花体字误成普通字 |
| 上下标及所属范围 | 帽子下的指数漏掉；`2^{sqrt(2 lg n)}` 只对 2 开方；上下标挂到错误节点 |
| 运算与关系 | 波浪路径箭头变直箭头；`≥` 变 `>`；上方的 `∞` 丢失 |
| 定界符 | floor/ceiling 变普通方括号；绝对值、范数、集合花括号混淆 |
| 结构 | 竖式加法被识别为分数；多行推导被拼成一串；矩阵缺分隔线 |
| 文本与标点 | 条件里的 if/otherwise 丢词；逗号、句号、公式编号遗漏；字面 `$` 变反斜杠 |
| 视觉呈现 | 下标不在正确位置、标签黏到公式、表格边线不显示、帽子或公式上下部被裁掉 |

示意：同样一条横线，下面两种结构不同，不能靠“看见横线”转换。

```text
1 + 2          a
─────          ─
  3            b
竖式求和       分数
```

左边保留操作数、求和线和结果行，右边才使用分子/分母。脚本不负责从 OCR 结果推断哪一种才对。

## 渲染脚本已处理的技术问题

`math_rendering.render_mathml(latex, display=True|False)` 会：

- 把 `aligned/align/gather` 等兼容布局转为 MathML 表结构；保留真正的行分隔。
- 识别 `\\[2pt]` 这种可选行距参数。它不是新的 `\[` 公式定界符；不能全局删除 `\[`。
- 生成后重新解析 XML，拒绝可见未知命令，包括 `\2pt]` 这种不会被 `\\[A-Za-z]+` 抓到的泄漏。
- 为 WebView2 补上单元格左右对齐及 `rowlines/columnlines` 的实际 CSS 边线。
- 正确处理显示公式的大运算符上下限、函数及其完整下标组后的间距；保留显式的源字体/显示样式。
- 保留 `\boxed{...}` 的 `comfortable-math-box` 标记及边框回退。
- 对单字母 `\mathrm{E}` 等显式正体保留分组，防止转换器把单字符优化回斜体。比较实际 `mi` 的字体/variant，不能只核对可见字符 E。

它**不会**自动把方括号改成取整符号，不会自动修正 OCR 数字、添逗号、改大小写，也不会判断推导的数学真伪。这些需要原稿证据。

普通正文中谈论 LaTeX、代码围栏里的命令、货币 `$1`、字符串哨兵 `$` 都可能是原文内容；不能用“清理未编译内容”的名义删掉。非显示的 MathML 源注释也不等于正文泄漏。

## OCR 与第二次模型检查的使用方式

1. 保存原公式资源、原始 OCR 输出和修正后的表达式。记录来源页、资源/位置标识和每次修正理由。
2. 先用少量具有代表性的公式验证识别、编译、排版整条链路，再扩大规模。
3. 模型返回 `uncertain: false`、第二次模型说“相同”，都不是通过证明。第二次检查既可能漏掉指数，也可能将两栏中的相同公式编号看成额外标签。
4. 不自动应用模型提出的“修正”。回看原公式或上下文，确认真实差异后修改。
5. 比较图要清楚区分原稿和候选。不得裁掉公式末尾、上限/下限或原稿右侧编号；两栏不要靠得让编号像落进了另一栏。
6. 将问题分成内容差异、排版差异、源稿疑点和误报，分别处理。仅字体、换行或编号横向位置变化通常不代表内容不同。
7. 每条检查绑定源图哈希、候选数学文本/MathML 哈希、渲染版本。公式或公共渲染规则变化后重新检查受影响项，不能复用旧图的“通过”。

完整性要求覆盖全部数学对象；检测、转换和差异队列不能只处理第一章。复杂多行式、特殊符号、低分辨率式和所有存疑项应逐项查看。即使采用自动对照，也要报告自动检查与人工式逐项视觉检查的真实范围，不声称二者等价。

## 行内与独立公式

- 行内公式属于所在句子，应与正文基线协调，字号继承正文。不要为每个变量或字体片段新建段落。
- 独立公式保持一个整体，编号和标点也要有位置。复杂推导可按原来的语义行排版。
- 先测量实际字形、编号和边线，再适度适配；不能裁掉根号、上划线、求和下限或最后一行。宽式缩放后若难读，提供可选择的真实 MathML 详情。长推导可按原语义行分组，不能把任何长结构一律压成微字。
- 用户禁止公式图片时，不能将 PNG、截图或转成路径的整式 SVG 当作替代。真正的示意图按 PDF 分类规则处理；不以图片尺寸或图号为豁免依据。

## 编译失败后做什么

1. 查看具体失败公式及原稿，检查 OCR 的反斜杠、花括号、行分隔和未知宏。
2. 修复有证据的转写错误，或将不支持的布局写成语义相同的标准结构。
3. 重编译、重新对照、再更新状态。
4. 仍无法确定时保留原始材料与问题记录，说明未完成的范围。不能以图片、占位符、丢弃内容或返回 `ok` 结束。

`build_reader.py` 默认阻止未渲染数学。`--allow-math-fallback` 仅适用于用户明确接受的诊断稿，不能导入成正式书；用户已禁止原始 LaTeX 时不得使用这个选项绕过要求。
