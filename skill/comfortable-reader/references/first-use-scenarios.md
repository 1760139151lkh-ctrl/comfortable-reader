# 首次使用验证：不给旧投诉作为提示

修改本技能后，用普通首次请求检查引导是否足够。不要把“熟悉这次调查的 agent 知道怎么补救”当成技能有效的证据。

如果进行独立评估，给执行者用户请求、技能和必要的原始样本，不给旧对话、投诉、预期答案或可抄的修复稿。使用隔离工作目录与只读生产环境；验证不能写进真实用户书库。不要为了降低难度而只给已经修好的 Markdown。

## 执行者看到的请求

这些请求本身故意不提醒常见错误：

1. “把这个带数学内容的 PDF 放进我本机的舒适阅读书库，和已有书一样方便阅读。”
2. “这个 EPUB 已经排好了，帮我放进书库。”
3. “这份文本帮我做成书，里面的公式也要看得见。”
4. “把已有的这本书完全重做，使用我给的新原稿。”
5. “帮我测试这本长书在十页模式里是否正常。”
6. “这个算法课本读着费劲，帮我改善一下阅读体验。”
7. “书库看着累、操作也不顺，帮我全面检查并改善。”
8. “刚才保存失败了，帮我把当前思考和代码完整备份下来，再检查能否恢复。”

## 评估者准备的原始样本

用合成或获准的短样本，覆盖实际失败方式：

- 一句话中间有斜体，段落跨源页；一个 span 中含不同基线的下标字符。
- 原公式含上下取整、帽子加指数、上置无穷符号、竖式求和横线、`\\[2pt]`、以及句末逗号。
- 一个有左上角空单元格的表；一个含字面 `$` 的字符串数组；一幅有箭头和颜色信息的示意图。
- 一张编号为 Figure 的纯数据表：不能只因有图号就跳过结构重建。
- 一个有字体、资源和多章节导航的正常 EPUB；一个缺资源或断内部链接的 EPUB。
- 正文语义错误但源 PDF 仍完整嵌入的草稿；所有字符已“分配”但顺序错乱的草稿。
- 一个只有三页内容、下拉菜单可以选十页的短样本。
- 被修改过、与旧验收哈希不同的最终 EPUB；不存在 `metadata.db` 的相似目录。
- 超过一栏高的算法，含物理软换行、右侧注释、高 case 括号和成本列；长图注超过两栏；一个有长词/NBSP 的标题。
- 同时含 `\mathrm{E}` 与斜体 E 的公式；字体/主题切换后才能暴露的旧样式累积。
- 十栏从章节边界直接重开；在全书索引生成中连续切换栏数；带 PDF 连字的搜索词。
- 一本单章节书：分别跳到第 3、8、15 页与末页，切换三栏等分数列宽后再测；不能把字符位置 3 当成屏幕第 3 页。
- 有真实书籍的隔离书库：短窗中的末项、选中着色面的小字、iframe焦点和隐藏空状态；保存失败时只在内存里的草稿，以及损坏的旧记录原始字节。

## 什么行为才通过

| 场景 | 执行者必须主动做的事 | 不能放过的失败 |
|---|---|---|
| 首次 PDF 请求 | 先核实书库与源结构，走 PDF 专用流程，先校准真实复杂样章 | 直接 `extract_text → add`；等投诉后才检查 |
| 原稿保全 | 分别验证源字节和可见内容 | 用“PDF 已嵌入、哈希相同”替代正文完整性 |
| 正常 EPUB 入库 | 保留原书资源/字体/spine，审计最终文件 | 为调用构建器而再次抽文并丢样式 |
| 数学 | 对照符号与范围；未知宏和泄漏失败时先修复 | XML 有效就接受错误公式；把公式改图片 |
| 表与图 | 保留表头/空格/字面字符和图的视觉编码 | 表头错位、删空格、把图转成不完整数字表 |
| 长书 | 正确分段、检查链接与实际响应 | 固定 PDF 页截图懒加载或一个巨大 XHTML |
| 长算法/图注 | 按步骤或段落续排，保持行号/注释/case 范围与图注归属 | 整体缩成微字；用高括号 bbox 导致步骤错序 |
| 长表与详情 | 按行续排、重复真实表头，跨对象打开详情时核对首行与末行可达 | 行数完整却正文微字，或新表沿用上件详情滚动而漏掉表头 |
| 字体与主题 | 继承阅读器角色、来回切换并查计算样式 | 每书硬编码 px 正文；旧主题规则累积；把正体 E 变斜体 |
| 交互与位置 | 明确打开面板；测试键盘、滚轮、搜索、返回、边界重开 | hover 侵占阅读区；索引反复重建；把稳定位置叫精确屏幕页数 |
| 十页验收 | 实际显示十个有内容的页，检查字号、边缘和行长 | 只截图下拉菜单“10”或三页加七个空白槽 |
| 入库 | 同一最终哈希、现有正确库、实际记录与内容一致 | 检查 A 导入 B、创建相似空库、种子入库后覆盖 |
| 完成声明 | 在安装版打开目标书并验证 | 把模拟器、源码编译、候选文件当正式交付 |
| 替换 | 精确识别目标并保留批注/进度等用户数据 | 凭标题删除、静默迁移 CFI、整份覆盖生产状态 |
| 整体体验 | 建立不同判断角度，实际完成导航/输入/恢复旅程，绑定修复后版本复验 | 用截图数量证明舒适，或复用修改前的证据关闭新问题 |
| 失败备份 | 导出当前编辑并实际测试同版导入；损坏记录另保原始字节 | 导出先依赖失败的保存，或备份能下载却不能恢复 |

## 已自动覆盖与仍须行为验证的部分

`test_reader_pipeline.py` 使用合成文件自动测试：行分隔、未知宏与数字反斜杠泄漏、边线、上下限、取整与标点、字面代码、原始字节、分段/链接、缺资源、禁止原始 PDF 一步入库、禁止未编译数学入库、不新建错误库、旧哈希/未决问题拦截，以及最终文件和重复身份核对。入库测试调用模拟接口，不触碰真实 Calibre。

这些测试不能证明真实 PDF 的 OCR 准确、agent 会正确分类每一幅图、所有视觉检查真的执行，或安装版能够正确呈现。必须单独报告这些剩余验证范围；不能因为测试全绿就把技能称为“保证任意 PDF 无损”。

阅读器层还须用真实/隔离原生窗口验证连续阅读、长结构与重开；仅检索技能里有没有某句话不是行为测试。独立评估只有在已获授权并有委派能力时才安排，不把它变成每次普通导入的额外审批。

评估若发现执行者需要额外提示才能做关键动作，把缺失知识补进相应流程，再用未给提示的新样本复测。不要只在验证说明中追加“评估者记得提醒”。
