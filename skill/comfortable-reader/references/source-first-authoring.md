# 从书籍源项目创作，按需要阅读与发行

本流程用于新建、持续修改或准备分享一本书；普通私人导入仍走 SKILL.md 的保真入库关卡。这里的“源项目”是一处能辨认内容与依赖的书籍根目录，可以在现有仓库或作者目录内，不要求每本书另建仓库。保持一份权威正文和资源声明；网页、EPUB、个人书库副本是从它生成的使用版本。不要先把唯一原稿放进 Calibre，再从生成 EPUB 中倒拆回来。

新书源目录不包含阅读器前端。当前共享界面在项目的 `desktop/src`，原生存储／运行在 `desktop/src-tauri`，浏览器使用独立的平台适配；`site/core.mjs` 管理通用内容声明和取得计划。网页构建调用同一套阅读与学习组件。需要新交互类型时先核对当前版本化能力；新阅读方式是产品变更，不能在新书测试中复制另一套前端。

## 当前已可用的入口与边界

先检查技能目录中可选的 `local-config.json`：它只保存本机的 `project_root`，不进入公共技能。实际核对该项目的 README、AGENTS 和工具入口；配置缺失或失效时再定位当前仓库。配置是定位线索，不是能力已验证或外部操作已授权的证明。

先定位当前仓库的 `tools/new_book.py`、`tools/check_book.py`、`tools/export_epub.py`、`tools/build_site.py` 和 `docs/FORMAT.md`；没有这套工具时不要假称以下命令已存在。Markdown 的每个文件以 `#` 标题开始，按文件名顺序成为一章。创建私有初稿：

```text
python tools/new_book.py --markdown path/to/chapters --out path/to/my-book --slug my-book --title "书名"
python tools/check_book.py path/to/my-book
python tools/export_epub.py path/to/my-book --out path/to/my-book.epub
```

简单文字 EPUB 可用 `--epub original.epub` 代替 `--markdown`，原文件不会被改动。当前导入器只处理标题、段落、简单强调与无序列表；遇到图片、数学、表格或其他不能保真的结构会停下。复杂 EPUB 保留原件，在隔离区按真实内容重建并核对，不用自动抽出的纯文字宣称完整。`new_book.py` 生成 `rights.status=review_required`，不会登记公共书目或个人书库。生成的标题、作者、说明、修订日期与原稿来源仍须人核，不能把占位字段发布。

书籍中的 `book.json` 持有稳定 UUID、章节 ID、修订、资源、来源与活动。正文以项目内相对路径引用；行内 `@source id`、`@resource id`，独立一行的 `@image id` 和 `@activity id` 连到相应对象。`@image` 的 PNG 会自动成为该章离线保存的必需图；代码、数据、媒体仍按活动或读者选择取得。来源卡即使未取得原件也显示题名、作者/机构、版本、页段、支持的论断和合法入口。当前图片格式受限于 PNG 和明确解码预算；其他媒体/组件只能按当前格式支持范围声明，不能把计划写成已实现。

浏览器已有版本化的 `least-squares@1` 计算能力：新书声明章内锚点、参数范围、必需 CSV、可选源码与观察目标即可接入，不因书名或章节号修改阅读器。它运行的是阅读器审核过的确定性算法，**不是书中 Python 代码**。Windows 原生活动沿用受控运行器；解释器、输出位置、已批准定义及资源的哈希和授权留在本机绑定中，具体接入先读 `learning-pack-tools.md`。公开书籍的原生运行不能仅凭浏览器内置计算通过就标为完成。书籍声明 `trusted=true`、shell、cwd 或环境变量不能赋权。公式可用当前支持的可读文字表达；复杂数学仍须走 MathML 保真流程，不能从小型 Markdown 解析器推断其已完整转换。

## 从同一源项目生成不同用途

私有预览可在一处独立的 `books` 根放书籍目录及 `publication-list.json`，列出要预览的 slug，然后运行：

```text
python tools/build_site.py --preview --books-dir path/to/private-books --out path/to/new-empty-preview
```

这个开关仅用于本机候选；公开发行只能使用仓库里的审核纳入清单，并须经过 `--release` 的归属、许可与资源检查。构建器只取声明的文件，生成按章正文、可独立选择的资源、内容哈希和静态 EPUB 回退。在线打开章节按需取必要正文/插图；选择保存一章、准备活动、取得独立资源、下载整本 EPUB 是不同动作。作者不用把大数据或运行环境打进每个书籍版本；对于不可切分的资源写清实际最小单位。普通 EPUB 仍给正文、活动说明、出处目录与资源说明，不以交互不可用换成空章。

同一构建产生完整 EPUB 与按章获取的 XHTML；网页不会先下载完整 EPUB 再隐藏其他章节。预先生成的 CFI 位置表避免在线全书索引暗中取完所有章节。首次准备共享阅读器需要项目的 Node 依赖。`python tools/reader_build_receipt.py build` 会从当前仓库构建 `desktop/dist`，给源码与构建文件逐项写入字节和 SHA-256 收据；`python tools/reader_build_receipt.py verify --dist desktop/dist` 可只读复核。之后可用 `--reader-dist <该受审构建>` 重用界面产物；构建器会核对收据、当前源码和构建文件，不再凭一个 `index.html` 接受任意目录。收据只证明本机来源和文件身份，阅读体验仍需另验。预览服务必须绑定本机地址；不把开启本机 HTTP 服务叫作公网发布。

保留既有 EPUB 字节的兼容预览可使用 `tools/preview_existing_book.py`，明确指定 EPUB、学习包、资源根和带上述收据的共享界面构建；它按 EPUB 容器、包清单和书脊解析原文件路径，不假定 `OEBPS`。该输出须标为这本 EPUB 的私人兼容预览，只用于本机核对，不会替未获权利确认的原件取得公开许可，也不能代替已安装舒适阅读书库的验收。学习提示、参考结果对应关系、媒体身份与专用运行适配属于书籍源；`tools/apply_study_profile.py` 可将同书同版的呈现说明合并到新学习包，而不改变正文和资源字节。运行适配本身也是需要单独审查、冻结哈希的代码，不是阅读时执行的组件。

若用户要加入自己的桌面书库，先核对那台机器的应用标识、已登记库、当前版本与原有批注；使用实际安装版的导入入口，把同源 EPUB 入库。连接同版书目可补上按需材料，保留本机正文字节。私人入库不改变公共目录，不能为了更新而按标题删旧书再导入。浏览器、隔离原生构建和正式安装版必须分别验收。

发布则单独审查代码、书籍文字、媒体、数据与字体的许可和来源，排除批注、进度、私密资料、凭据、缓存与个人结果。参考结果另标来源、修订、输入、环境与再现条件。审计源码、构建文件、EPUB 内部和拟推送历史；有凭据须处理失效或轮换。具备发行条件仍不自动上传。仓库 `skill/comfortable-reader` 是维护主本，本机目录是部署副本；使用 `tools/sync_skill.py --target <安装目录> --backup <独立备份目录>` 先看计划，核对后加 `--apply`。只同步许可范围内的技能文件，保留 vendor 与个人配置，不反向提交它们。

修改正文、图、活动或来源时，先改这处源项目，更新 `revision`/`revisionModified`，重建受影响产物。保持书 ID 与语义锚点；对旧批注和运行结果先做版本对照，失配时保留旧记录等待映射，不默默覆盖。来源目录移动后，只重绑本机环境；相对资源关系与 ID 不需改写。若应用允许直接改书籍生成物，须把改动带回源项目并处理冲突，否则不得用库中副本静默盖过作者稿。

## 交付前验证这条流程

从不依赖现有教材或私人书库的一份正文开始，在隔离源目录加入真实公式、插图、来源和已有能力的活动。用共享构建在网页与隔离桌面打开同一版内容；记录实际取得的章节和资源，完成一次计算再返回原句。核对书籍 ID、正文与资源哈希，不用截图里的标题代替身份。

移动完整源目录后重建；不改正文和声明时，产物应保持相同内容身份。再修改一句正文或一个活动参数，增加修订并重建，核对受影响文件改变、无关资源可以复用。新旧产物都保留；不直接覆盖个人笔记与草稿，也不靠删除重导掩盖版本关系。检查阅读器源码未因新增这本书而改变。

分别记录源码检查、浏览器、隔离原生构建、正式安装版、公开站点的证据。源项目可迁移、小样可运行与任务指定的既有真实书籍接入是不同义务；测试示例应有明确身份，不替代正式教材入口。技能主本的版本与本机部署文件逐项核对，保留私有配置和 vendor；没有完成的验证保持待验证，不能把本文件的流程描述当成能力证明。


## 已发布项目与复杂书的维护

当前维护地址是 https://github.com/1760139151lkh-ctrl/comfortable-reader 。地址不代表仓库始终公开；先核实际可见性和访问权限，保留维护者已选择的私人范围。首次参与先读仓库 `docs/CODEX.md` 与 `CONTRIBUTING.md`；用户已有 clone/fork 时优先使用它，不创建重复产品。技能和源码的安装位置由本机确定，公共技能不携带作者配置。

书籍既可以是简单 Markdown 源，也可以是 `sourceFormat: epub-source@1` 的语义 EPUB 源。后一种以正向列明的 XHTML/MathML/CSS/PNG 和 OPF 为当前正文，校验与导出入口仍为 check_book.py/export_epub.py/build_site.py。已有复杂书不能经简化导入器转成纯文字；保持源数学和内容身份，升级修订后从同源重建。历史实验引用的原稿快照另有身份，不把它当第二份当前正文维护。

正式书目与创作示例分开：books/publication-list.json 只列已审核的完整教学作品，短小演示在 examples/books。不要因为工具测试成功，把小样提升为正式教材，或以小样取代任务指定的真实书。实际发布授权与第三方再分发权分别核对；用户已经明确授权的范围不重复索取笼统批准。

较大参考检查点在 release-assets.json 绑定独立 Release 文件与 SHA-256。构建完整公共站点前可用 tools/prepare_release_assets.py 查看计划，显式 --download 才取得；构建私有小书不要求下载它们。不加载模型、不运行教材代码也能完成阅读、校验和预览。缺少公开分发条件的材料必须保留准确来源与影响说明，不能用合成输出替换原实验。
