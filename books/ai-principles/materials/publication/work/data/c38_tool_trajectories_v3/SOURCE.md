# C38经修订的工具轨迹：真标题、模拟目录版本与复制位

本版不是新语料或外部预训模型。活动资料根在C18 `article_source_index.json`前600篇**训练文章**及固定词表，实际标题选择、作者乘法/直答/缺席编号、原划分和许可边界见[v1源卡](../c38_tool_trajectories_v1/SOURCE.md)。C38主模型父权重仍为C19→C25混合支。v3清单SHA `61062747975d022a851d1fadb7c303bbd2b4597f572bd5f4ee99424bea53cbbe`；训练2480行，验证/测试各167行。`validation.jsonl`和`test.jsonl`与v1、v2同名文件**字节相同**，各题/答案不因训练失败被重新抽样。

v1首轮模型会写调用，却在40道真标题验证题上最终0对。v2只改**训练**资料：对原190个训练标题ID各造6个作者模拟目录版本，同一ID在这些版本里返回另一条仅来自训练标题的值，迫使“答案跟当前工具返回走”；另造数字复制练习。它不是声称WikiText原文章的真实标题曾改变，轨迹里标`author_simulated_catalog_snapshot`及另一个训练来源ID。v2总训练3056行、验证/测试原题不变；乘法验证改善而标题仍0/40。v2额给最终答案4倍训练目标的单独支也未修好标题，均留原报告，不把模拟版本叫真实百科变更。

具体查看分词器发现v1/v2在 `T: Weather buoy` 里的首词带ByteLevel前导空格，例如 `ĠWe`；`A: `作为宿主前缀后，原回答片段单独从`Weather`开始却被拆成`W`,`e`,`ather`。模型若试着“照刚才那些编号复制”，首先便不相同。v3因此把`A:`后那一个空格归**模型生成的第一枚片段**，将`" Weather buoy\n"`作为助手段分词。对190条训练真标题，源码逐条核`T: 标题\nA:`里的**值与换行token ID**等于对应回答段token ID。v3还保留1140条作者模拟目录版本，另重复已有直接词例224次并加200条作者数字复制题，使直接题不被数字复制资料过度淹没；训练类数为乘法600、标题1330、直接480、缺席70。每条总真实输入最多85个位置，未截题/答案。

轨迹切分仍把工具定义和用户问句作条件，助手第一行是其应输出的调用或直接回复；若已调用，`T: ...\nA:`由宿主提供，只有助手最后的答复目标参与这段的训练损失。v3 `tokenized_v3`对四段**分别编码**、再串接，因果输入与下一位标签对齐；`copy_observation_value_start/length`明确哪些token来自工具值，`copy_final_target_ordinals`从0给每个应回答token编号。这份额外来源标注是在训练小型复制门时提供的**宿主信息**，不是C19原模型从字符串自行发现的角色结构。

当前真实执行记录：v3只训练原四层模型的动作/答复时，同167验证题100整题、真标题0/40；固定这份模型后另训195参复制门，验证149/167。训练/验证定好后，`work/results/c38_tool_first_internal_test.json`**首次**打开同来源167题，整题138，乘法92/100、真标题22/40、直接12/12、缺席12/15。观察替换诊断只在验证题完成，故意给乘法返回错误积+1只检验模型是否跟随，不代表那道算术题答对。详细时序、SHA、每类错误与额外结构边界见`work/verification/C38_pretest_decision.md`和`work/verification/C38_tool_learning_protocol.md`。首次测试已开，后续同题都只能称事后。
