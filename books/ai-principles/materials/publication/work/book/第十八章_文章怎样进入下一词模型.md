# 第十八章　文章怎样进入下一词模型

第十七章留下了一个看似小、实际很硬的问题。我们已经能让一个位置只读前文，算出下一个编号的概率；但那个编号从哪篇文章来？文章何时结束？两个从未相邻的段落能否被拼成同一段“前文”？如果这些事交给含糊的“准备数据”，遮住未来的模型仍可能在错误的题目上学得很认真。

第十五章曾用 WikiText 的真实文章训练两词窗口模型，留出了整篇验证、测试文章，也看到了词表把大量罕见原词并成 UNK 的代价。那套工作已经说明“原文自己给下一词答案”，却不能直接喂给现在的因果 Transformer：一个词窗口不等于一段 128 个位置的上下文；其按空格分词的编号也不能无损保留空白。我们沿用那批已固定来源的文章，重新做一条能看清每个位置的路径。旧实验的损失与新实验的损失不因都叫“下一词”便可以横向排高低。

<a id="eighteenth-source"></a>
## 先认出这是哪份文字

今天电脑上的输入是 WikiText-2 raw-v1 的三份 Parquet 文件，不是即时抓取的百科网页。第十五章已核过 [Salesforce 发布仓库](https://huggingface.co/datasets/Salesforce/wikitext)、[原论文](https://arxiv.org/pdf/1609.07843)和本机原文件的哈希。这里的 raw 表示该变体没有先把稀词替换成 UNK，**不表示**网页排版、标点和空白从 Wikipedia 的 HTML 原样保留下来。第一篇的正文中已经有被分开的标点，以及数据集特有的 @-@ 记号。我们能够精确回读的是**这份数据提供给模型的文本**，不能凭“回读成功”宣称恢复了当年的网页。[来源、版本与使用条件](../data/wikitext2_raw/SOURCE.md)和[新文章索引](../data/wikitext2_causal/article_source_index.json)都保留在本机。

2016 年 Merity 等人推出 WikiText，不只是为了让一个语言模型多读些词。他们讨论了长距离前文和罕见名字在既有基准上难测的问题；较长的 Wikipedia 优质文章使“前两词够不够”与“前几十词、几百词能否帮忙”成为更真实的问法。他们同时研究能从前文复制罕见词的 pointer-sentinel 模型。文章和模型是同篇论文的两项工作，不能把前者倒说成专为几年后的 Transformer 生产。([Merity 等，2016，摘要、§1、§4](https://arxiv.org/pdf/1609.07843))

第十五章第一次辨认文章时有过实际教训：一条冰球条目中的“= Goals ; A =”长得像标题，单看等号会把它误切成短“文章”。已经修过的解析器要求顶层标题两侧的空行条件也满足，再决定新文章从哪一行开始。本章在原 Parquet 行上复用这条判断：每篇从自己的标题行到下一篇标题前，按源行次序连接；只删末尾多余换行，不吞掉内部空格。训练、验证、测试分别是 600、60、60 篇。第一篇训练文章“Valkyria Chronicles III”的标题在来源从零计数第 **1** 行，第一段正文在第 **3** 行。这两个行号分得开，读者可以在原包中逐行找回，不必相信作者手敲的样本。([解析与来源身份](../code/prepare_causal_wikitext.py)；[第一篇源行及文本哈希](../data/wikitext2_causal/manifest.json))

这些文章的原著和贡献者并没有因为被装进一个训练数组而消失。数据仓库顶部与数据卡对许可的表述并不完全一致；本机教学保存来源、文章标题、行跨度与文件哈希，只摘短片段解释计算。若要另行公开发布语料或模型生成的大段原文，仍需按相应文件和文章核实际许可、署名与用途，不能把“能够下载”改写为“可以任意再分发”。这是数据来源的一部分，和文件内容可重现同样重要。([本机来源记录](../data/wikitext2_raw/SOURCE.md))

<a id="eighteenth-history"></a>
## 模型愿意读更多文字时，研究者怎样改变给它的文字

第十五章的 UNK 提醒我们，输入单位本身会改变题目。2016 年 Sennrich、Haddow 与 Birch 面对神经翻译里的人名、复合词和少见词，选择把常见字符片段合成可复用的**子词**。他们借用了 Gage 1994 年为压缩提出的高频相邻对替换思想，但翻译论文要解决的是开放词表下怎样表示和生成词，目的不是把磁盘文件压得最小。一个罕见名字即便没有完整词条，仍可能拆成已有片段；片段越细，一句话所需预测步数通常也越多。这给词表大小与序列长度一项真实交换，而非“新分词器天然更懂语言”。([Sennrich 等，2016，§1、§3.2](https://aclanthology.org/P16-1162.pdf))

第十七章末读到的 2018 年生成式预训练，把书本文字和遮住未来的 Transformer 接起来；同年 Kudo 与 Richardson 的 SentencePiece 又强调可从原始句子学子词，不必先把每个语言都交给外部词切分器。它提醒我们：若前处理早已抹去空白、强行规定“词”，后面的模型无法自己找回那部分信息。本章的 WikiText raw-v1 已有上游加工，因此我们能保证**本阶段不再丢掉它给出的空白**，却不能把这份资料假装成未经加工的自然网页。([2018 生成式预训练论文，§3.1、§4.1](https://cdn.openai.com/research-covers/language-unsupervised/language_understanding_paper.pdf)；[SentencePiece，2018，摘要](https://arxiv.org/abs/1808.06226))

2019 年 GPT-2 的作者从至少获得 3 点 karma 的 Reddit 外链收集网页：人曾经选择或认可链接，被当作一种粗略质量筛子。这样当然也带入了这些用户愿意分享什么的偏向，不是“全网均匀抽样”。论文报告：从约 4500 万条外链取正文，经过 Dragnet、Newspaper 提取器、启发式清理和去重，实际使用的早期 WebText 有略多于 **800 万篇、40 GB** 文本。他们选字节级 BPE 来处理广泛的字串，特意去掉 WebText 中的 Wikipedia 文档，以减少与常见评价集的重叠；随后还用片段重叠检查评估集与训练文字。于是“读更多网页”不再只是扩容问题：取得什么网页、正文提取错掉什么、重复的网页让测验变得多熟，都会改变结果的含义。那篇论文自己就记录了 WikiText-103 的测试集中有文章也出现在其训练集，并没有把“官方切分”当作完全无污染的保证。([GPT-2，2019，§2.1—2.2、§4](https://cdn.openai.com/better-language-models/language_models_are_unsupervised_multitask_learners.pdf))

到 2020 年，规模又改变了清理的取舍。T5 团队从 Common Crawl 的网页提取文字建 C4：过滤掉不像完整句子的行和太短的页，删除反复出现的三句片段，还用语言识别器筛英语。他们专门比较了过滤方案，说明这些决定本身也是可测的实验变量。譬如“整页出现左花括号就删”对他们选定的英文自然语言任务可有理由，对一份要学程序的资料却会直接删掉不少正常代码；不能拿一套数据的清理规则当另一套数据的普遍真理。([T5，2020，§2.2、§3.4.2](https://jmlr.org/papers/volume21/20-074/20-074.pdf))

同年 GPT-3 团队在网页之外加入书和百科：论文写明其 2016—2019 年的 Common Crawl 原始月度分片压缩文本约 **45 TB**，过滤后约 **570 GB**，并在文档层做近似去重。更关键的是训练抽样不按原始库大小走；表 2.2 中过滤网页约 **4100 亿**片段、训练权重约 **60%**，百科约 **30 亿**片段、权重约 **3%**。后者虽小，却会在训练中被重复取到多轮。2020 年末首次提交的 The Pile 则明确由 **22 类**来源组成，包括学术文字、问答和百科，公开讨论不同领域资料和构建过程。不同项目没有同一张“最干净文本”的终极清单：语料选择连着任务、许可、评价与希望学到的分布。([GPT-3，2020，§2.2、表 2.2](https://arxiv.org/pdf/2005.14165)；[The Pile，2020 年末首版，摘要、§2](https://arxiv.org/abs/2101.00027))

本机没有数十亿网页，也没有假称复现这些语料工程。选 WikiText 的理由较窄而明确：来源和切分可查，整篇文章足够让我们遇到真正的边界，规模足够让这台电脑从随机参数持续训练并留出测试。正因为历史上的大系统曾在来源、清洗和混合上作不同选择，我们必须把**本次只用一个来源**写清楚。今后若再加书、代码或对话，来源比例要成为明确决定，不能把文件拼在一起就叫“自然混合”。

<a id="eighteenth-split"></a>
## 先决定什么能参与学习，再看重复

机器学习里的验证文章用来选处理或训练方案，测试文章用来在选择结束后评价。若先读了测试文章里的所有词，再回头让分词器据此决定该合并哪些片段，测试虽然没有直接进模型参数，却已经参与了**输入表示的设计**。于是本章先固定三份原文件和整篇划分，再只拿 600 篇训练文章学分词器。验证、测试沿用上游文章分组，不把一篇文章的开头交给训练、结尾交给测试；本章的一次梯度核算也只读训练块，后续持续训练须守住同一条边界。换一份 tokenizer 或清洗规则会改变题目，需要新版本和新比较，不能暗中重算旧成绩。

此前已检查三组没有相同的标题或完整文章哈希。本章再从每篇文本切出段落，把大小写折叠、连续空白合为一个空格，只对**至少 20 个空格分隔词**的段落求精确哈希。训练对验证、训练对测试、验证对测试的匹配数都为 **0**。这是一项有边界的核查：它找不到换几个词的转述，也找不到被拆行、被摘录、跨段落复制的全部情况；短段落没纳入。GPT-2 的重叠分析恰好说明为什么不能从一个零数便推断“没有任何泄漏”。([本机清单与算法](../data/wikitext2_causal/manifest.json)；[GPT-2，2019，§4](https://cdn.openai.com/better-language-models/language_models_are_unsupervised_multitask_learners.pdf))

<a id="eighteenth-tokenizer"></a>
## 不再把罕见词统统压成同一个编号

第十五章保留最常见的 10,000 个完整空格字段，模型在测试目标中约 **12.57%** 的原字段落入 UNK。那项实验比较的是映射后的词预测，结果本身有效；但若我们希望模型区分原来不同的罕见名字，就得改变表示。最细可以从 UTF-8 的 256 种字节值起步：任意能以 UTF-8 编码的文本都有表示，代价是一串中文字符或较长英文词会变成许多步。另一端是给每个完整词独立编号：步数短，字典却大，未见词可能又得合并为 UNK。**字节级 BPE**从字节可回读的基础出发，在训练文字中反复给常一起出现的相邻片段一个合并单位；合并顺序保存下来，验证和测试只能用已经学好的顺序编码。它是数据驱动的压缩式选择，不是根据词法学给每段盖“真实词根”印章。

本机使用已安装的 tokenizers 0.23.2 库，训练目标词表定为 **8192 项**，其中 PAD、BOS、EOS 占 0、1、2 号。库负责高效地统计与保存合并表；[准备程序](../code/prepare_causal_wikitext.py)明确指定了只用训练文章、字节级预切分、不自动在前面添空格、最低合并频数 2，以及字节级解码器。训练出 [tokenizer 文件](../data/wikitext2_causal/tokenizer.json)后，程序重新载入它，逐篇将三组全部 **720 篇本阶段文本**编码、解码，逐字符比较，均能精确回到各自送入编码器的文本。三组文章都可被**使用**这个固定词表表示；只有训练组参加了**学习**这个词表。回读检查核的是表示的可逆性，没证明模型已学会用这些编号写话。

实际合并表的前几步可用来理解“按相邻频数选择”具体做了什么。字节级显示把一个空格写成 Ġ；在训练资料统计中，先有 Ġ 与 t 的合并，再有 h 与 e 的合并，稍后又把 Ġt 与 he 合起来。于是短串“ the”最终只需一枚片段 Ġthe，编号 **263**；对比之下，没按同样模式高频出现的串还可能被拆成几个片段。合并的条件是训练文本里相邻片段的统计和既定次序，**不是**程序认识英文定冠词。编码时也不是每碰见字母 t 就任意合并：它依保存的合并规则、预切分边界和排序走。[实际合并次序](../data/wikitext2_causal/tokenizer.json)与下方的首篇回读可以彼此核对。

第一篇标题给出一段可在电脑上核的路径。来源模型文本开头是“空格、等号、空格、Valkyria Chronicles III、空格、等号、换行”；换行后才是 Senjō 开始的正文。分词器显示的头几个片段为“Ġ=”、“ĠValky”、“ria”、“ĠChronic”、“les”、“ĠIII”。屏幕上的 Ġ 是**这个字节级分词器用来显示空格的字形**，Ċ 对应换行；它们不是来源文献里实际印出的 Ġ 或 Ċ。“Senjō”里的非 ASCII 字节显示也可能长得不像完整字符，必须经字节解码还原，不能逐片段把显示字形当成语义。前六个普通片段编号是 **303、7849、3724、6348、658、3052**。在第十五章词级模型里作为 UNK 的 Homarus，这里连同后面的空格与 gammarus 编成 **8** 个编号，仍能解回“Homarus gammarus”。这只解决**原字串能否表示**，并不保证模型理解这类海生动物。([首篇及罕见词真实记录](../data/wikitext2_causal/manifest.json))

8192 不是从某个最佳准确率定理算出的。词表大一些，常见片段能变长，序列可能缩短，但嵌入表和最后对全部候选打分的矩阵也变大；词表小一些，矩阵省了，注意力处理的序列和预测步数可能增多。两头的运行成本都要算。尤其不能把旧词级模型每**词字段**的困惑度与新模型每**子词片段**的困惑度直接比较：一个答案被切成不同数量的预测事件。若只比较两种模型给**各自固定编码路径**的分数，可以先固定同一批原字节、文章起止和确定的编码规则，累计各路径的负对数，再按共同的字节数归一；必须把这个量写成“规范编码路径每字节代价”，不能偷叫原字串的完整概率。本章也尚未作这项跨模型比较。

为什么还要分这两层？刚才的空格加 `the`，本机分词器默认编码成一枚 `Ġthe`，编号 **263**；但[实际回读探针](../results/tokenization_ambiguity_probe.json)还核到 `[259,260]`（`Ġt`、`he`）和 `[223,86,260]` 也都解回同一个“ the”。确定性编码器只选第一条路；一个没有额外禁止这些词表项的生成模型，却可能说出后两条。若从 BOS 到 EOS 问它生成**这段原字串**的概率，须把所有解码为该字串的互不相同编号路径的概率相加；只算 `[263]` 是指定路径的概率。这一步与前面“一个可见结果可能对应多个隐藏解释，要把它们合起来”是同一概率道理，不要求现在穷举所有路径。词表换了以后，连路径集合也会变，故本机两个不同单位的 PPL 不能靠换个分母便成为原文概率排行榜。

<a id="eighteenth-stream"></a>
## 每篇文章自己开始，也自己结束

让第 \(i\) 篇文章经过固定 tokenizer 后得到 \(n_i\) 个普通编号 \(u_{i,1},\ldots,u_{i,n_i}\)。我们为它单独组成
\[
s_i=(\mathrm{BOS},u_{i,1},\ldots,u_{i,n_i},\mathrm{EOS}).
\]
BOS 告诉第一个位置“这篇开始了”，不要求网络去预测 BOS；EOS 是文章末尾真实要预测的目标，不能漏掉，也不能把下一篇的标题当作它的自然续词。第十七章的遮未来规则在一篇内部依然适用，但“遮未来”本身**不会**阻止模型读到上一篇文章。如果训练程序先把所有文章简单接成一个长数组，除非另外设计边界重置，上一文尾会变成下一文头的假上下文。

本章选择容易核对的一种分块法：每篇**单独**从偏移 0、128、256……取连续位置，最多 128 个输入；标签取每个输入的右邻。用公式写，一块从偏移 \(a\) 开始，其第 \(t\) 个有效位置（\(t=0,\ldots,127\)）是
\[
x_t=s_i[a+t],\qquad y_t=s_i[a+t+1].
\]
只有两个位置仍在当前篇的流中时才有这条训练问答。下一块的首个输入可以是上一块最后一个**目标**；这个编号作为新块的起点再出现一次，但它只被当过一次目标，没有被双计损失。每块内部的注意力从自己的首个输入起算：文章虽然可能有几千片段，模型在这次设计里最多读本块的 **128 个位置**，不能把“训练资料是整篇文章”说成“模型实际看见了整篇文章”。跨块长期记忆是另一种模型或训练设计，需要另行交代。

第一块尤其直观：输入开头是 **[1, 303, 7849, 3724, 6348, 658, 3052, 303, …]**，答案开头是 **[303, 7849, 3724, 6348, 658, 3052, 303, 319, …]**。第一位置读 BOS，答第一个“空格+等号”；第二位置已读该片段，答标题里的下一片。数字 1 不是原文字节 1，而是我们明定的 BOS 特殊编号。文章索引 0、第一块偏移 0、源行 1/3 和这组编号都在[同一份记录](../data/wikitext2_causal/manifest.json)；可从[原数组](../data/wikitext2_causal/train_blocks.npz)复算。

最后一块通常不足 128 个真实问答。我们用 PAD=0 把输入补齐为矩形，同时把没有答案的位置在标签里写为 −100。−100 不是词表中的“错误词”；PyTorch 的交叉熵用它表示**这一位置不计损失**。另存的布尔 attention_mask 在真实输入列为真、PAD 列为假。于是这里有三件不同的事：PAD 是占位输入，−100 决定哪些位置有训练目标，遮未来与 PAD 列的许可表决定读取能看哪里。不能只处理其一便宣称边界完整。

<a id="eighteenth-loss"></a>
## 被平均的是哪些预测，谁又真正影响了谁

一批块的输出在每个位置给 8192 个候选编号打分。设 \(m_{b,t}=1\) 表示第 \(b\) 块第 \(t\) 位有真实目标，否则为 0；把可见前缀输入写为 \(x_{b,\le t}\)。本章交给下一章训练器的平均负对数是
\[
L(\theta)=
\frac{\displaystyle\sum_b\sum_t m_{b,t}
\bigl[-\log P_\theta(y_{b,t}\mid x_{b,\le t})\bigr]}
{\displaystyle\sum_b\sum_t m_{b,t}}.
\]
分母是**真实目标数**，不是块数乘 128，更不是文章数。每个有答案的位置都可沿共同的输出、前馈、注意力与嵌入计算回传误差；−100 的位置不给这次目标的误差。若某位置是 PAD，仍可在张量里算出没有用途的输出，忽略其损失即可；为了使任何位置也不能把 PAD 当文本读，注意力的第 \(t\) 行只许可第 \(j\) 列同时满足 \(j\le t\) 且该列是真实输入。当前查询即使落在 PAD 行，至少还可以读当前块先前的真实输入，不会出现一整行被遮到没有可读键而使 softmax 失效。

把[实际代码](../code/causal_batch_probe.py)中最要紧的两处放在一起看，轴的含义与上式逐一对应：

~~~python
triangle = torch.ones(length, length, dtype=torch.bool, device=ids.device).tril()
allowed = triangle[None, None, :, :] & real[:, None, None, :]
sum_loss = F.cross_entropy(
    logits.reshape(-1, logits.shape[-1]),
    labels.reshape(-1), ignore_index=-100, reduction="sum",
)
mean_real = sum_loss / int((labels != -100).sum())
~~~

triangle 的第 \(t,j\) 项只问“\(j\) 是否晚于 \(t\)”；real 的第 \(b,j\) 项只问“这一列是不是实际输入”。广播后，第一维是批次，最后两维分别是查询位置与被读位置。把 logits 的批次与位置展平，是让交叉熵逐个有效位置取正确答案的负对数；reduction 为 sum 后，我们**自己**数 `labels != -100` 的位置作分母，与公式一致。当前右邻任务恰好每个真实输入都有一个目标，因此这个数暂时等于 `real.sum()`；但两张表的**职责不同**，不能因为这次相等就把它们当成同一张。完整程序还把一个真满块和同一篇文章的尾块送进随机初始化的一层自身读取，计算一次梯度，但没有执行优化器更新。因此这项运行核的是数据、遮罩和损失能连到参数，不冒充语言能力。

那篇首文的第一块有 **128** 个真实目标，最后一块从偏移 **4992** 开始，有 **114** 个真实目标和 **14** 个 PAD 占位；最后一个真实目标是 EOS=2。两个块合计应以 **242** 个目标作分母。本机一次随机初值前向得到每真实目标负对数约 **9.177**；若错把 256 个矩形位置当分母，数字会被假压到约 **8.675**。遮未来或 PAD 的所有禁看权重实测为 **0**，查询投影的梯度范数约 **0.345**，但还没有参数更新。数值随随机种子和实现可核，它们的解释范围更重要：较小的错分母数值并不表示更会写文章。([逐项运行记录](../results/causal_batch_probe.json))

还可以只改一项条件来检查两张表为何要分开：让首块最初那个 BOS **仍是可读输入**，但暂时不把它右邻的 303 算进损失，即只将这项标签改成 −100。程序里可读输入仍有 **242** 处，计损失的目标却只剩 **241** 处；这一变体的正确平均约 **9.180**，错除以可读输入数只得到约 **9.142**。原模型当然不会因为遮掉一项标签而学得更好；这里核的是“什么进入上下文”与“什么提供训练误差”可以分开决定。后面若给模型一段可读提示、却只要求它学习接下来的回答，这个区别会直接承担训练责任，本章已把分母和读取许可的位置讲清。([同一次本机变体](../results/causal_batch_probe.json))

整份训练资料含 **600** 篇、约 **269.45 万** 个普通子词片段；每篇还有一个 EOS，所以共有 **2,695,132** 个真实预测目标，被放入 **21,353** 块。所有块若都填满共有 2,733,184 个位置，其中 **38,052** 个是无损失占位，约占 **1.39%**。验证为 60 篇、284,331 个目标，测试为 60 篇、325,674 个目标；每组每篇的 EOS 只出现一次，所有普通片段都恰好成为一次目标。程序执行中检查了这些等式、每篇不跨文档、BOS 不进入目标、PAD 不进入真实输入。检查能抓准备代码的这类错误，但不评价一个训练好的模型会否写出可信内容。([完整准备清单](../data/wikitext2_causal/manifest.json))

## 只用一个来源，数据仍然有“谁说话更响”的问题

上式让数据集里的每个真实目标计一次，并不是平均每篇文章一次。第 \(i\) 篇有 \(n_i+1\) 个目标，在一轮完整遍历的**总损失**中按项数占 \((n_i+1)/\sum_k(n_k+1)\)；长文章即使不比短文章“更可靠”，也会贡献更多项。本机训练文章的普通片段数最短 **352**、中位约 **3248.5**、最长 **22655**。首篇的 5106 个目标约占整组目标的 **0.189%**，略大于“每篇等权”时的 \(1/600\approx0.167\%\)。这些数让“按所有块洗牌”背后的权重可见。若要每篇等权，可先抽文章再从其中抽位置，或对每篇总损失按其目标数归一；但优化噪声、长文章被看见的频率和最终分布都会改变，不能无言换规则后还把两次曲线当同一实验。下一章若用小批次逐次更新，每步在**本批**目标上求平均不等于一次性对全训练集求梯度；特别是含较多尾块时，必须把取块和分母的约定记入训练结果。

多个来源时还要再加一层选择。假设第 \(s\) 类来源在训练抽样中被选中的概率是 \(q_s\)，选中后从其文档或片段抽目标，那么总目标可写为 \(\sum_s q_s\,\mathbb E_{(x,y)\sim D_s}[-\log P_\theta(y\mid x)]\)。\(q_s\) 是**训练时选择的权重**，不必等于磁盘上该来源的字节或文章比例。GPT-3 论文表 2.2 明说其混合没有按各库大小成比例；The Pile 也以多类组成和不同取样权重为设计问题。我们的实际数据只有一个 WikiText 来源，因此此处 \(q_{\rm WikiText}=1\)，没有“新闻占几成、书占几成”的运行结果。公式是未来加新来源时必须明确的决策位置，不是今天已做过混合的证据。([GPT-3，2020，§2.2、表 2.2](https://arxiv.org/pdf/2005.14165)；[The Pile，§2、表 1](https://arxiv.org/pdf/2101.00027))

## 在电脑上从同一条原文走到损失

在本项目根目录的 PowerShell 中依次运行。第一条从已保留的原 Parquet 重建 tokenizer、文章索引和训练块；第二条用刚保存的 tokenizer 核一段字串的多条可回读编号路径；第三条在首篇真实块上核一次前向、损失和梯度：

~~~powershell
$env:PYTHONUTF8='1'
python work/code/prepare_causal_wikitext.py
python work/code/tokenization_ambiguity_probe.py
python work/code/causal_batch_probe.py
~~~

本机运行需 Python、NumPy、pyarrow、PyTorch，以及本章使用的 tokenizers 0.23.2；完整来源文件已在项目中，脚本不向网络取新语料。若重建的 tokenizer 或数组哈希与[当前清单](../data/wikitext2_causal/manifest.json)不同，应先核运行库版本、原文件与处理代码，不把不同版本悄悄当成同一模型的输入。[文章索引](../data/wikitext2_causal/article_source_index.json)给标题和行跨度；[训练数组](../data/wikitext2_causal/train_blocks.npz)给 input_ids、labels、attention_mask、article_index、first_token_offset 五列。任取一块，先用 article_index 与偏移定位文章，再按保存的 tokenizer 把编号读回去，最后检查每个非 −100 的目标是不是其输入的右邻；读者能沿这条链从文字走到某一项损失。

现在训练器真正拿到了可使用的材料：不跨文章的输入、固定词表、右邻标签、逐位置可见性、只由训练文章学得的表示，以及没有打开来挑方案的测试组。下一章该接过的是另一件完整的工作：从随机权重在这些训练块上反复更新，在有限显存与时间里保存和恢复；用验证资料选检查点，再对留出的测试文字和独立生成分别作相称的评价。本章的一次随机前向已经把错误的分母、漏掉的 EOS 和假跨篇上下文排开，却不会自己长成一场预训练。

## 拿真实块改一次条件

1. 第一块输入从 BOS=1 起，标签第一项是 303。若把输入与标签完全相同地复制，第一项的“正确答案”会变成什么？模型还能从前文预测真正的第一片段吗？
2. 第一篇末块有 114 个真目标、14 个 PAD。若单独在这块上算损失，分母取 114 还是 128？如果最后的 EOS 被错写为 −100，整个训练集会少多少个 EOS 目标？若只遮首块第一项的**标签**、输入仍是 BOS，哪张表改变、哪张不变？
3. 若先把所有 720 篇接起来才按位置切 128，哪两种边界会出问题：训练/测试文章之间，以及同一训练组中相邻两篇文章之间？只保留三角遮罩能解决哪一个？
4. 把词表改成 16,384 项后，为什么不能直接对比“每片段平均 NLL”？若要比较规范编码路径的每字节代价，应先固定什么？即便做到这些，为何 `[263]` 一条路径的概率还不必等于原字串“ the”的完整概率？
5. 假设把一篇 20,000 目标的长文与一篇 500 目标的短文各读一轮。现行逐目标平均下，长文对总损失的项数是短文的多少倍？若按文章均匀抽样且每篇只随机取一个目标，答案会怎样改变？这两种做法都能被称为“没有偏好”吗？

**核对。**第一题若照抄，BOS 会被当成自己的答案，目标右移关系坏了；当前设计先看 BOS 再答 303。第二题分母是 114；若**每篇**都丢末尾 EOS，全训练组会少 600 项。只遮首项标签时 `labels != -100` 少一处，`attention_mask` 里的 BOS 仍为真，后面的真实位置仍能读取它。第三题跨组会泄漏留出资料；同组跨篇会造出“上一篇接下一篇”的假文字。三角遮罩只挡当前块的未来，挡不住已经排在前面的另一篇。第四题需固定原文本、起止边界和编码规则，在同一原字节单位上累计；`[259,260]` 等别的编号路径也能解出同一字串，只算 `[263]` 没有把它们的概率加进去。第五题项数为 40 倍；每篇抽一个目标时两篇被选的机会相等，但长文每个具体位置被看见的机会相应更小。两种抽样各有定义的目标，不能脱离目标说它们都天然“无偏”。
