# 第三十八章　模型怎样学会请求工具并使用返回

上一章的本机服务已经能把一段文字续写出来。假如续出的文字恰好是 `call mul(37,42)`，第十九章的网络依然只是选了一串分词编号；**它没有在自己的权重里做乘法，更没有因为写了这串字符就得到1554**。要让这个动作有用，模型先要在该调用时选择调用、写对两个数；宿主认出一个获准的请求，实际运行乘法并把1554送回来；模型再读到这个返回，完成回答。若问“WikiText第144篇训练文章的标题”，同样得由能读本机文章索引的工具给出那篇的值。

这章研究的是其中可学习的行为：什么时候直接回答、什么时候发工具请求、参数从问题里怎样来、看到返回后究竟有没有用它。执行者的权限和失败恢复仍是真问题，但暂且用两种**只读**本机工具，让“模型的动作”和“工具观察”各有清楚身份。上章那条不做工具训练的弱小文章模型、第二十五章在真实指令示范上适配过的模型，都会作为实际起点；我们不会突然换上一套强大的外部聊天模型，然后把它的本领写成这四层小网络学会的结果。[已服务的模型及能力边界](第三十七章_训练好的模型怎样接住一次请求.md#thirtyseventh-weight-origin)；[指令适配的实际来源](第二十五章_文章模型怎样学着回应要求.md#twentyfifth-source)

<a id="thirtyeighth-four-voices"></a>
## 四段文字放在一列，作者不能把它们当同一个人写的

先看一条本机真实可执行的轨迹：

~~~text
Tools: mul(a,b) computes product; title(id) reads WikiText article title.
Q: Multiply 37 by 42.
A: call mul(37,42)
T: 1554
A: 1554
~~~

第一行由训练者给出本轮可用工具的说明；`Q` 是用户问题。第一条 `A` 是我们希望模型自己能写出的**动作**。宿主只在动作符合获准格式、参数是10—99的整数时，才运行Python的整数乘法并插入 `T`。最后一条 `A` 才是模型读完返回后应写的答案。训练时作者可以提供一份带正确动作与答案的**示范**；实际评价时两处 `A` 必须由模型自由生成，宿主不得看标准答案替它挑 `mul` 或把它写错的数字改正。

标题任务的 `T` 来自另一份实际资料：第十八章整理过的 WikiText-2 raw-v1 前600篇**训练文章**的索引。我们从中只取270个较短、可在这台128位上下文模型里完整处理的英文标题；其标题文字确实来自已有文章，编号却是**本书整理文章时排出的行序**，不是Wikipedia公共ID。这个模型在第十九章预训练时已经看过这批训练文章的文字，所以测试一个未作为工具示范出现过的编号，不等于标题的每个词对模型一生全新。另一类问题要求它直接复述短词，不该调用；不存在的文章编号由工具返回 `NOT_FOUND`，答案应作相称回应。[标题来源、作者规则和许可边界](../data/c38_tool_trajectories_v1/SOURCE.md)

构成轨迹后，两种常被混淆的“会”就能逐项检查了。若模型写对 `call title(144)`，只说明它给了宿主一个能解析、参数正确的请求；若它收到 `Weather buoy` 却回出另一篇标题，它仍不会**用观察**。如果这一次有用的是工具读文件的结果，不能反过来说那份新标题来自模型参数。把这些贡献分清，是学习工具能力的起点，不是给现成系统贴一个“Agent”名称。

<a id="thirtyeighth-history-early"></a>
## 把话变成可执行要求，早于聊天模型；训练来源却随时代改变

上章沿2017—2025年推断服务研究走到今天。这里为弄清“语言与外部动作”的来源，明确沿**另一条更早的线**回看：1971年前后，Winograd的SHRDLU研究让程序在受限的积木世界里理解一部分语言、对世界物体执行操作。当时的研究条件是**已定义的封闭世界、物体关系和程序过程**，不是有一台先在海量文章上训练好的Transformer，然后等它自己发现网页工具。本轮能直接核到的是MIT同期研究报告对该研究的定位；原学位报告扫描未稳定取得，我们不把后人讲的细节冒充逐页读到。[1971 MIT研究报告](https://www.mit.edu/~dxh/marvin/web.media.mit.edu/~minsky/papers/PR1971.html)

从封闭积木世界走向真实资料库，中间并没有空白四十年。1983年Grosz介绍TEAM时，眼前的难题是**同一句人话与数据库里的文件、字段并不按同一套名称组织**：若每换一座数据库就由语言专家重写大量规则，系统很难迁移。TEAM把用户语句的逻辑含义、领域概念及具体资料库的存取对应分开，还请熟悉数据库的人提供新领域信息。它能让人用语言访问已存事实，却不是一个会从海量用户聊天自我训练的语言模型；当时真正付出的是领域词表、概念和数据库结构的取得。[TEAM，1983原论文§A—D](https://aclanthology.org/A83-1006.pdf)

到1996年，Zelle与Mooney的CHILL已经把“自然问句→可执行数据库查询”当作**从配对例子学习**的问题：在美国地理问句与查询配对上学习解析器控制规则。2005年Zettlemoyer与Collins又以句子和逻辑表达式的配对，学习可组合的语法及对分析打分的概率模型，检验地理和工作岗位数据库。这些方法仍需要明确的目标表达式或查询资料，也没有让模型任意操作一台电脑；但“工具动作怎样从自然语言条件里学出来”绝非今日聊天模型横空发明。([CHILL，1996原论文书目与摘要](https://www.cs.utexas.edu/~ai-lab/pub-view.php?PubID=51437)；[Zettlemoyer、Collins，2005原论文第1—2页](https://people.csail.mit.edu/mcollins/papers/uai05.pdf))

到2016—2017年，又有另一种模型条件：神经网络可以把一句问话生成一个小程序，另有明确的解释器或数据库**真正执行**它。Neural Symbolic Machines把序列生成的程序交给Lisp解释器，在Freebase查询任务里用执行结果与搜索约束学习；Seq2SQL把自然语言送成SQL，在已有表上运行，并让执行答案影响学习。它们的语言范围和工具接口由资料设计者给定，但已清楚表明“可微模型选程序”和“不可微的外部运行”可以合作；因此不能说2023年之后模型才第一次会产生可执行的东西。两篇的执行环境、监督强弱又不同，也不能把它们直接改称今日开放网络助手。([Neural Symbolic Machines，2016预稿/2017论文](https://aclanthology.org/P17-1003/)；[Seq2SQL，2017预稿](https://arxiv.org/abs/1709.00103))

2021年的WebGPT研究面对长答案的资料查找与引用问题，让已预训练的GPT-3在文字浏览环境中搜索、点击并引用；**人先留下真实浏览示范**，模型模仿后，又有人比较答案，用来训练评分和做结果选择/优化。浏览器提供页面内容，人工示范提供动作路线，模型负责在条件下生成下一个动作或回答；一条有引文的回复同时借了这三种来源。原论文最优配置包含行为克隆后的奖励模型拒绝采样，不是“只要把浏览器打开，权重就自动知道怎么查”。[WebGPT原论文摘要与§2—4](https://cdn.openai.com/WebGPT.pdf)

<a id="thirtyeighth-probability"></a>
## 谁的概率能拿来教模型，谁的返回只是外部条件

前几章已经有语言模型的条件概率和第二十三、二十六章的动作概率。现在给它们各找一个对象。设用户问题及已知历史为 \(h\)，模型生成的请求为 \(a\)，宿主按请求得到工具返回 \(o\)，模型随后写答案 \(b\)。一次完整交互的概率可以按来源分解成

\[
p_{\theta,E}(a,o,b\mid h)
=p_\theta(a\mid h)\,P_E(o\mid h,a)\,p_\theta(b\mid h,a,o).
\]

下标 \(E\) 指**执行工具的环境**，不是模型参数的另一个名称。若 `mul(37,42)`是稳定确定的纯函数，正确请求发生后 \(P_E(o=1554\mid h,a)=1\)；若是查询可能失败、资料可能更新的外部系统，该项也有其自己的条件与变化。模型没有在本次采样里“选择工具返回1554”——它选的是请求及后续回答。仅对这次**模型自己做出的动作**使用策略梯度时，样本的对数概率项来自

\[
\log p_\theta(a\mid h)+\log p_\theta(b\mid h,a,o),
\]

而不是把 \(\log p_\theta(o\mid h,a)\) 塞进同一条“动作的对数概率”。否则奖励会错误地鼓励模型为**环境已经返回的文字**争功。结果得分可以在交互完成后由题目验收者提供，例如这道乘法是否答对；它本身也不是一个能机械地从解释器穿过离散输出传回网络的导数。若训练者另想教模型**预测工具返回**、模拟环境，或继续对整份记录做普通语言建模，可以设计给 \(o\) 的目标；那是换了学习任务，不是数学上禁止观察token有loss。[前文结果反馈的真实概率更新](第二十六章_回答得到分数以后谁在学习.md#twentysixth-score-gradient)

另一条可行路线先有可信示范，不必让小模型碰运气采到第一次正确请求。把轨迹的分词位置记为 \(x_1,\ldots,x_n\)，令 \(m_t=1\) 表示第 \(t\) 位是这份教学安排要模型生成的第一条或最后一条`A`内容，其余用户输入、工具说明和`T`返回取0。我们选择的**行为克隆式监督目标**是

\[
L_{\rm A}(\theta)=-\frac{1}{\sum_{t=2}^n m_t}
\sum_{t=2}^n m_t\log p_\theta(x_t\mid x_{<t}).
\]

分母是参与学习的**模型目标token数**。第 \(t\) 项不计损失，不等于把它从条件历史 \(x_{<t'}\) 中删掉；工具返回不作自身答案，后面的回答仍可以读它。如果把整份记录的每个真位置都计入同样的下一token目标，会得到另一项 \(L_{\rm all}\)，平均对象和梯度都会不同。我们在一条真实训练标题轨迹上用同一已训模型核数：只计两处助手，共11目标、平均NLL约 **0.270**；整份文字计67目标、约 **7.457**，输出头两条导数方向的余弦约 **0.190**。这不是谁普遍较好的研究胜负，只证明“loss mask放在哪儿”确实改变模型被教的事。[同一轨迹的输入、目标和梯度探针](../results/c38_loss_source_probe.json)

代码还有一个容易把来源写错的半步：模型在输入位置 \(i\) 的分数预测**下一位** \(i+1\)。所以标签标记应跟**目标位置的作者**移动，而不是拿当前位置输入是谁写的来决定。v3准备程序把工具说明、问题、第一条助手、工具返回、第二条助手分别分词后串接，再令 `labels[t]`只在后一位属于助手段时保留该编号；其它目标为 `-100`，但 `input_ids`仍保留真工具返回。[逐段编码与下一位遮罩](../code/c38_tool_data_v3.py)及[真实训练程序](../code/c38_tool_train.py)可以逐项对照，模型不是通过一个不明来路的`train()`突然获得工具技能。

这件事在[现行准备程序](../code/c38_tool_data_v3.py)里只占很短几行；`chunks[2]`是宿主工具段，`tag`在这段取0：

~~~python
seq = [1] + sum(chunks, [])             # 1 是本书 BOS
tag = [0] * (1 + len(chunks[0])) + [1] * len(chunks[1]) + [0] * len(chunks[2]) + [1] * len(chunks[3])
labels = [value if marked else -100 for value, marked in zip(seq[1:], tag[1:])]
~~~

真正的程序还把末尾补到128位，且另留`attention_mask`说明哪些**输入**是真token。`tag`移到 `tag[1:]` 才与 `seq[1:]` 的目标对齐；工具返回对应的输入编号仍在 `seq[:-1]`，后段因此能读它。若只把 `labels` 中的返回位改成 `-100`，并没有“删除观察”。

<a id="thirtyeighth-historical-routes"></a>
## 2022—2023年，示范、筛选与交互不是同一条流水线

WebGPT有人演示怎样浏览；若想减少每种工具都要人手写大量轨迹的成本，就要问**哪些自生成调用值得留下来训练**。2022年的TALM已经让预训练T5先产生工具输入，遇到约定的分隔符由工具返回，再生成答案。它不是从全无信息中凭空自我提升：先有少量工具使用示范，还有任务输入及已知的目标答案。系统反复生成候选调用和回答，只把达到答案检查条件的轨迹加入下一轮训练。这样构造资料可以有效，但“生成最多许多候选、检查后留下”的计算与标准答案来源都是真正付出的代价；若所有候选都错，筛选器没有可留下的成功示范。[TALM原文§2.1—2.2](https://arxiv.org/html/2205.12255)

几个月后的ReAct研究把已有大模型的思考文字、动作、环境观察交替写进轨迹。在知识题里，它明示 `search`、`lookup`、`finish` 的不同作用；较早的主要比较用少量人写轨迹做**提示**，另有用正确轨迹微调较小PaLM的实验。提示使当次条件改变，微调才写回权重，不能把两类成绩都叫“ReAct训练法”。它在某些微调支里把 thoughts/actions/**observations**整段作为序列目标，这和我们上节只计助手动作的选择也不同；要看实验到底想学会模仿整份交互记录，还是单独抓模型负责的行为。[ReAct原论文§2—4](https://arxiv.org/html/2210.03629)

2023年Toolformer又试一个特殊的自筛法。它从已有的 **6.7B GPT-J** 起步，用每种API的少量示范令模型提候选调用位置和参数，真实运行工具，然后看：插入“调用及返回”后，原来后面的文字是不是更好预测？若把那段原文的加权NLL记作 \(L\)，论文比较有返回的 \(L^+\) 与“不调用”和“调用但不给结果”两项中较好的 \(L^-\)，只留下满足 \(L^- - L^+\ge\tau\) 的候选。这是**后续文本预测价值**的筛选，不等于我们乘法题的任务正确率，也不是模型自己证明百科事实为真。选出的调用和结果随后插回原文，用普通增强文本LM目标微调——**工具返回也会进入它的训练文本目标**，所以不能援引Toolformer说“一切工具观察位必须遮loss”。论文还承认其办法当时不能串多个工具，小模型使用工具的收益在其设置里并不明显。[Toolformer原文§2、§4.4、§7](https://arxiv.org/html/2302.04761)

这些路线回答的是不同资料问题：有可信人写动作时可以直接模仿；有原文可比较预测时可以按后续NLL筛调用；有可执行答案验收时可以留下通过的轨迹；可以承受在线采样和结果反馈时，也可用前节的模型动作概率优化。第26章二选一REINFORCE已经在本书同源模型上跑过**真的参数更新**；本章实际选择的是工具示范SFT，再对返回使用单独训练一个小部件。我们会推清用结果反馈时概率应落在哪些位置，但**没有把本章工具调用声称训练成PPO/GRPO或通用工具RL**。历史上不是人人按“示范→筛选→RL”统一顺序走了一遍。

<a id="thirtyeighth-data"></a>
## 给自己的小模型资料时，真正让它练什么

本机这项工程只允许两种工具：`mul(a,b)`接两个10—99整数，用Python整数给出准确积；`title(id)`按第十八章训练文章索引查一个短标题，缺席编号返 `NOT_FOUND`。此外有无需工具的“照写这个词”。题目、动作示范、最后回答的生成规则由**作者**准备，不冒充真人留下的自然工具对话。原C19→C25混合旧资料指令支仍用同一词表，C25所选第三轮检查点是本章的父权重；题目在本机最多85个真实输入位置，不需要裁掉半个返回才能塞进128。[原资料/划分来源](../data/c38_tool_trajectories_v3/SOURCE.md)

v1按**整道乘法数对、整篇标题编号、直接题的词与句式组合**把资料分成训练916、验证167、内部测试167。标题字符串都来自原WikiText的训练文章，因此“新标题编号”是**没做过这道调用训练题的编号**，不是预训练时从未见过这个英文标题。乘法两因子和四种固定问法可能跨组出现，也不考英语自由改写。这些条件很窄，却让我们能把模型选择、参数、观察与最终答案分别核算。验证用来选轮和诊断，167道内部测试直到下一节方案锁定以后才由模型评估进程打开。

实际推断没有用预设选项约束动作。模型在 `A:` 后从**全8192项词表**逐项贪心生成一行；若它写出合法 `call ...`，宿主严格解析并执行所请求的两个纯操作，哪怕参数不合题；若它没调用，直接把那行当作回答。若名字/括号/参数不合法，记调用失败，不用标准答案替换。得到 `T:` 后，模型再自由生成一行。它最多调用一次；后续讨论多步的论文不能为这项窄任务多添虚构的步骤。[真实自由评估程序](../code/c38_tool_evaluate.py)

<a id="thirtyeighth-first-failure"></a>
## 会选工具了，为什么读不出工具给的标题

先用C25父权重直接对**验证**167题按上段规则作答，整题 **0/167**。这不是说模型从来没读过英文或完全不懂乘号；它说明在这套陌生的`call`格式与一条返回的任务上，不给对应轨迹训练，它不能自由走通一次完整交互。接着从同一父权重用v1示范更新四层网络：每批四种题各取6条，只对助手请求和最终答案计交叉熵，验证四类NLL平均挑第1800步，保留代码与状态。[首支训练记录](../runs/c38_tool_action_sft_1800/train.json)

训练后的**验证**并非全无用处：100道乘法题都判断该调用，其中94道把两个输入数字写对；40道真标题题都请求查询，其中35道把编号写对；12道不该调用的直接题有10道整题对，15道缺席编号题全对。可是乘法完整答对只 **43/100**，标题竟是 **0/40**。第一处具体失败是“91乘26”：模型确实写 `call mul(91,26)`，Python给 `2366`，它却回答 `266`。另一处是编号29：请求和工具返回 `Forward Intelligence Team` 都对，模型最后却报了另一个名字。[第一轮逐题自由输出](../results/c38_tool_validation_free_1800.json)

这几项数把训练对象分开了：**是否需要工具**和**工具名/参数**已经有很窄但真实的学习；**利用返回**还没接上。若作者只报“调用格式100/100”便离开，读者会像用户原对话那样不得不追问“工具回来以后它真会用吗”。我们因此没有把此处封成一个成功的小阶段，而是在尚未打开内部测试时改条件、核对另一环节。[第一次测试之前的方案锁定记录](../verification/C38_pretest_decision.md)

<a id="thirtyeighth-copy-problem"></a>
## 不会照读，是损失太小、资料太少，还是表示里藏了绊脚处

先怀疑训练示范都只给同一个编号一个固定标题，模型可能记住“编号→某个常见名字”，却没有理由每次看新的`T`。v2在**训练组**给190个真实标题编号各造6个作者模拟的目录版本，令同一编号在不同情景返回别的、同样来自训练组的标题；只有当前观察能分辨该答哪个值。另加数字复制练习，想帮助它按原样带回乘法工具给出的四位数。验证/内部测试的问题文件原字节不变。这一改动使乘法验证整题到 **79/100**，但标题仍 **0/40**，直接短词题还从10/12降到6/12。把最后回答位置的训练损失另外加四倍，验证反只 **73/167**，标题仍0。增加目标权重不会自动建立复制未知文字的计算路径。[这几支的方案、来源与验证结果](../verification/C38_tool_learning_protocol.md)

再把一条返回真的送进分词器检查。`T: Weather buoy`中的第一个英文词有前导空格，旧ByteLevel-BPE把它从 `ĠWe` 之类的编号开始；我们原来把宿主的`A: `连空格一起先塞给模型，助手单独要生成的`Weather buoy`却从 `W`,`e`,… 开始。人看见的是同一个“Weather”，模型看到的**复制来源和目标编号并不相同**。v3让`A:`后那个空格也由助手生成，使训练组190条真标题的返回值与回答值/换行在BPE编号上逐项对齐；同时保留模拟目录版本、重新平衡直接词练习。同一验证题上，乘法整题75/100、直接11/12，但标题**仍0/40**。修一个真正存在的编码绊脚处，不等于证明小模型已经学到任意新字符串的精确复制。[v3逐标题编号核验及来源](../code/c38_tool_data_v3.py)；[同题验证](../results/c38_tool_validation_aligned_copy_2400.json)

到这里，失败不该再被一行“多训一些”遮过去。固定宽192、四层、原本以文章右邻预测起步的小模型，在这些短模板上已经可产生许多合式请求；但新的多词标题是一个不同的运算要求：读入外部返回，保留它每一个片段的顺序，再一项一项写回。我们可以给这个操作一个更明确的结构，而不是让读者误以为“观察进了上下文”就足以保证它自动形成。

<a id="thirtyeighth-copy-math"></a>
## 一个明示来源的复制通道，究竟由谁提供了什么

先把额外条件讲清，再谈结果。宿主知道某一段token确实是`T`返回的**值**，可以把那段的起止位置和工具状态（找到/未找到）交给一个小部件；它还知道助手已经写了几个回答token，因而给当前回答位置一个序号 \(r=0,1,2,\ldots\)。这是一种设计者提供的**结构偏置**，不是原C19网络突然通过梯度自发标出了可信证据。如果工具返回本身错、被恶意改写，清楚地复制它也不会让事实变真。

设工具值被切成 \(o_0,o_1,\ldots,o_{m-1}\) 个编号，连同末尾换行也保留。要给回答第 \(r\) 项一个“先试着照第 \(r\) 项取”的候选，我们在来源位置 \(j\) 放权重

\[
\alpha_{rj}=\frac{\exp[-\lambda|j-r|]}{\sum_{k=0}^{m-1}\exp[-\lambda|k-r|]},
\qquad \lambda=\log(1+e^u)>0.
\]

距离越远，权重越小；\(u\) 可训练，但这个**按序号靠近**的形状由作者选定，并非从任务唯一推得。若来源里同一token编号出现多次，要把那些位置的权重加起来，才是复制为该编号 \(v\) 的概率 \(c_r(v)=\sum_j\alpha_{rj}\mathbf1[o_j=v]\)。与此同时，原四层模型仍给词表一个 \(p_{\rm LM}(v\mid h,a,o,b_{<r})\)。再用其当前位置活动 \(z_r\) 和宿主给的“查到值”位 \(f\) 算一个介于0和1之间的门 \(g_r=\sigma(w^\top[z_r;f]+b)\)，两种候选按此合并：

\[
p(v\mid h,a,o,b_{<r})=(1-g_r)p_{\rm LM}(v\mid h,a,o,b_{<r})+g_r c_r(v).
\]

为什么这次梯度能教门打开？对示范正确编号 \(y\)，只看 \(g_r\) 改一点时，\(-\log p(y)\) 的导数是
\[
\frac{\partial[-\log p(y)]}{\partial g_r}
=\frac{p_{\rm LM}(y)-c_r(y)}{p(y)}.
\]
若返回值当前位置确实有 \(y\)、原词表却给它低概率，分子为负，增大复制门能减小损失；若工具返 `NOT_FOUND` 而要回答小写的 `not found`，同序号来源候选不一定有正确编号，门可以保持关着、让原模型来生成。这里没有要求对Python乘法或文件读取求导；梯度只过**我们新添的可训练门与距离尺度**。实际新增193个门权重、一偏置和一距离参数，共 **195** 项；四层旧权重在这一轮冻结。[具体门与位置权重的程序](../code/c38_copy_gate.py)

代码里的关系和式子可对上：`softplus`把尺度保持为正，`softmax`沿返回值位置归一，`scatter_add_`把可能重复的来源编号权重合到词表编号上；`sigmoid`算门，最后混合两份完整分布。重要的是 `copy_line` 在每个新回答token后重新用已有前缀算当前位置活动，再按当前 \(r\) 选下一项。宿主只标来源段和状态，不直接替模型发最后答案；但按序号提示已经很强，所以这项实验检验的是**加了明确复制通道的模型**，不能包装成原四层LM自然拥有一般检索理解。[代码实物](../code/c38_copy_gate.py)

运行时拿到了当前返回值的编号 `source` 后，候选概率与上式的混合在代码里确是同两个对象：

~~~python
attention = (-scale * distances).softmax(dim=0)
copy = torch.zeros(model.cfg.vocab, device=device)
copy.scatter_add_(0, source, attention)
probabilities = (1 - mix) * logits[0, -1].softmax(dim=-1) + mix * copy
~~~

`scatter_add_` 是“若两个返回位置有同一个编号，把两处权重加给词表同一格”，并不替模型判这段返回是否可信；这四行也没有在宿主里偷偷把标准标题直接写成最终答句。

<a id="thirtyeighth-results"></a>
## 这道窄题变好多少，又留下哪些实际错误

我们先只用工具训练/验证组教那195项门参数，用验证最后答复NLL在0—400步选第400步；原v3模型的工具选择与参数生成权重始终冻结。v3原模型在同167道**验证**自由题整题 **100/167**，加复制通道后 **149/167**：乘法75→93/100，标题0→31/40，直接仍由原模型完成11/12，缺席编号14/15。上段导数与每位置编号相等说明**为什么这条新路径可学**，但它依赖的来源范围/序号来自宿主，不能从这49题提升声称“模型独自变成通用搜索专家”。[复制门训练与验证逐题输出](../runs/c38_copy_gate_400/train.json)、[同题自由验证](../results/c38_tool_validation_copy_gate_400.json)

为检查它究竟有没有看见返回，而非只记住题号，我们在验证集中固定12道参数正确的乘法、12道参数正确的标题。对每道保持用户问题与已生成调用不变，另把返回改一个值：乘法故意给真实积 **加1**，标题换成另一条真实已训标题。正常与替换后的48次答复都照着**这次给的返回**变化。[观察替换的逐条记录](../results/c38_observation_validation_intervention.json) 这证明当前结构会使用所标的返回值，也马上暴露新的边界：若乘法工具坏到返回错数，模型照念错数不算它“算对了”。将来必须另管工具来源、错误和授权，不能拿“观察利用”一项抵销所有可信性责任。

方案及权重在打开内部测试之前已经锁进[决策记录](../verification/C38_pretest_decision.md)。第一次对167道未用来训练/选轮的内部题运行**全词表自由生成→严格只读执行→自由回答**，得到：

| 题目 | 题数 | 应不应该调用判断正确 | 参数完全正确 | 整题答对 |
|---|---:|---:|---:|---:|
| 10—99乘法 | 100 | 100 | 92 | **92** |
| 真实训练文章标题 | 40 | 40 | 29 | **22** |
| 短词直接回答 | 12 | 12 | 不适用 | **12** |
| 不存在的文章编号 | 15 | 15 | 12 | **12** |

合计 **138/167**。[首次内部测试完整逐题收据](../results/c38_tool_first_internal_test.json)还显示：乘法100道虽都选择调用，只有97条语法可解析；标题40道调用都可解析，实际参数29条正确，回答跟随**当次工具返回**33条。问“标题编号10”，模型有一次却请求编号109；它再准确转述109的标题，仍不算完成用户题。问编号375，它正确调用并看见`Cougar`，却回答`Cougars`，多了一个字母。这些错误把“是否调用、参数、返回利用、最终任务”放在四张不同的检查表里，避免一个总数吞掉具体失败。

标题来自同一600篇训练文章，乘法题用两位数和固定英文模板，最多只需一条获准工具调用；此处既没有在未知工具仓库里找API，也没让模型连续查两页、编辑真实文件或处理用户中途改要求。2023年API-Bank原本就把“已知API时会调用”“先找到未知API再调用”“多API计划并调用”分开，并统计未调用、名字/参数/格式错等不同失败；我们只覆盖第一级里极窄的两种只读操作。[API-Bank原论文§2—4](https://arxiv.org/html/2304.08244) 这不否定本机学得的部分，它让下一次要改善的具体位置可见。

<a id="thirtyeighth-to-bigger-work"></a>
## 一次准确查询之外，训练与宿主怎样继续合作

工具一多、问题一长，单条正确调用和最后一行文字就远远不够。2024年的SWE-agent在仓库修复中强调**模型能看见、能操作的计算机接口**如何影响实际改文件与测程序；有终端权限不等于模型会选对文件、补丁和测试。[SWE-agent原论文](https://arxiv.org/abs/2405.15793) 同期的τ-bench让客服样任务带动态用户、领域API与政策约束，不只看调用字符串是否像格式，还看多步交互后的任务状态和重复运行的一致性。[τ-bench原论文](https://arxiv.org/abs/2406.12045) 本章纯乘法/标题工具几乎没有不可逆作用，故没有资格把自身138/167和那些任务成绩放同一轴比较。

到2025—2026年的研究，训练者仍在解决“如何把长的真实执行经历变成可更新的信号”。Agent Lightning的2025预稿尝试把宿主交互轨迹拆成RL可用的状态/动作/反馈；2026年8月的v1.0预稿更直接讨论**宿主拥有执行循环**时，训练器如何从模型请求/回复对重建样本，以及重新分词、合并样本、优势和损失如何归一。ICLR 2026的CodeGym则从可运行代码题合成多步、可验证的工具环境，另有训练起点和评估条件。这些工作不是证明给本机小模型任意一张工具表就会产生研究级智能；它们说明真实提升仍要组织资料、运行、反馈和可核的任务，不是“多写一句请调用工具”。([Agent Lightning 2025预稿](https://arxiv.org/abs/2508.03680)；[2026 v1.0预稿](https://arxiv.org/abs/2608.17528)；[CodeGym ICLR 2026论文页](https://proceedings.iclr.cc/paper_files/paper/2026/hash/1e4322fddd833f83c855660ac65e428d-Abstract-Conference.html))

在本章自己的数据里，这个问题已有一个小而具体的形状：一份旧权重并不懂调用格式；作者给它动作/答复示范后，它开始会发请求，却仍不会精确复述新的多词返回；把观察当条件的loss、文字片段的编号边界和另加的复制结构，每一项都改变了可学信息。真实的学会并非一个`tool_use=True`开关。下一章接的不是更多同样的短标题，而是宿主执行开始可能修改世界时，模型看见超时却不知工具是否已做过的困难：谁授权、谁留下收据、重试会不会造成两次副作用。**模型发对请求**是这里已经讨论的一件事；**现实执行可靠**仍须由实际执行系统给出新的证据。[工具调用与执行失败的连续试样](../../样章/S03_工具返回并不是模型说的话.md#s03-p11)

<a id="thirtyeighth-practice"></a>
## 在自己的电脑上改一项条件

以下命令在活动包根目录运行。首项只核作者已选模型上一条真轨迹的mask与梯度；随后从本书C25父检查点、已保存的v3训练与验证资料再训一份行动模型，在**自己刚训的**行动权重上训复制门，最后只用**已使用过的验证组**作自由调用/返回核查。新路径避免覆盖作者第一次测试收据；若再跑同一测试文件，也只叫复核。[完整运行口径和路径](../verification/C38_tool_learning_protocol.md)

~~~powershell
Set-Location '.'
python work/code/c38_loss_source_probe.py --out work/runs/c38_my_mask_probe.json
python work/code/c38_tool_train.py --data-dir work/data/c38_tool_trajectories_v3 --out-dir work/runs/c38_my_action --steps 2400 --lr 0.0002 --validate-every 100 --per-kind 6
python work/code/c38_copy_gate.py --action-checkpoint work/runs/c38_my_action/best.pt --out-dir work/runs/c38_my_copy_gate --steps 400 --lr 0.01 --validate-every 20
python work/code/c38_tool_evaluate.py --split validation --data-dir work/data/c38_tool_trajectories_v3 --checkpoint work/runs/c38_my_action/best.pt --copy-gate work/runs/c38_my_copy_gate/copy_gate.pt --out work/runs/c38_my_validation.json
~~~

先预测三种改动的后果，再动参数：把最后的`--copy-gate`去掉，调用格式和标题复述应分别受哪一项影响？把`T:`整行从模型第二次输入删掉，刚才的概率式哪个条件不见了？若仅把复制门调得始终接近1，遇到`NOT_FOUND`而期望写小写`not found`时又可能怎样？本章已给全部参考实现，练习不要求你凭空发明一个安全执行器；由此产生的错误、证据和下一步判断，才是自己可以继续研究的部分。

<details>
<summary>核对思路</summary>

1. 去掉门仍用同一v3行动权重，调用的名称/参数生成不会因这个命令直接换权重，但工具后的新标题精确复述在验证里是0/40；有门时31/40。其它题也要按各类实际结果看，不能由一项数据推所有调用都一样。
2. \(p_\theta(b\mid h,a,o)\)会失去实际 \(o\)；若程序还用旧的复制位置，索引已经不再指向工具值，更不是同一输入条件。遮掉**预测目标**与从输入删掉观察是两种动作。
3. `NOT_FOUND`的字母/编号和小写`not found`不同；此时复制候选可能不含正确目标，门需允许普通词表分支。只要宿主返回可能不可靠，复制准确也不能替工具来源和事实验收作证。

</details>
