<a id="first-question"></a>
# 第一章　程序会做事，经验怎样留下来

给一张新卡片，两个程序都能说出它属于哪一类。第一个程序的判断条件由人逐条写好；第二个程序的判断条件里有几个数，这几个数曾随着有答案的卡片而改变。仅看这次输出，我们分不清它们。要知道第二个程序究竟学了什么，必须追到它收到的记录、使用的计算和被改动的数。

这也是本章的任务。读完以后，我们要能亲手写出这样一个小程序，并准确回答：一条训练记录是什么，答案是谁给的；一次预测用的是哪几个数；程序算错时改的是输入、答案、临时分数，还是以后也会使用的参数。然后再问一个必要的边界问题：即使修改办法没有算错，选定的规则是否有能力表达我们想要的分类？

<a id="first-history"></a>
## 先看问题是怎样分开的

<a id="history-1943"></a>
1943 年，Warren McCulloch 与 Walter Pitts 研究的是神经活动能否用逻辑来描述。他们把一个神经元在某个时刻是否活动理想化为“是”或“否”，再问连接起来的单元能够实现怎样的逻辑关系。这件事给出了一个重要可能：许多简单的开关组成的网络，可以执行有结构的计算。但“这种网络能表示某种运算”与“网络会从经验中找到合适连接”是两问。论文谈到学习造成的持久变化时，也特别提醒：用不变网络作形式上的等价替换，并不是对真实学习过程的生理解释。我们以后会借用开关和网络的数学语言，却不能把这篇论文改写成一套已经能训练今日模型的程序。([McCulloch 与 Pitts，1943，重印本第 99—101 页](https://gwern.net/doc/ai/nn/1943-mcculloch.pdf))

<a id="history-1949"></a>
1949 年，心理学家 Donald Hebb 从另一侧追问记忆如何留在神经系统里。他提出，若一个细胞的活动反复参与引发另一个细胞活动，两者之间的作用效率可能发生持久变化；他还用细胞群的组织来讨论知觉与行为。在第 4 章，他把这种连接变化明确当作待检验的生理设想，而不是已在实验中观察到每个细节。这个设想让“连接本身会随经历变化”变得具体，却没有替我们规定：面对一张附有正确类别的卡片，计算机应该把某个权重恰好加多少。把 Hebb 的假说直接写成现代监督训练公式，会抹掉中间仍待解决的数学和反馈问题。([Hebb，《The Organization of Behavior》，1949，导言与第 4 章；所读重印节选第 50—51 页](https://www.cs.cmu.edu/~bhiksha/courses/deeplearning/Fall.2016/pdfs/Hebb.1949.pdf))

<a id="history-turing-1950"></a>
1950 年，Alan Turing 在《Computing Machinery and Intelligence》中提出了另一种切入办法。他当然讨论了机器能否在文字问答中让人难以辨认，但文章末节没有停在这项检验上：如果直接写出一个“成年人的完整心智程序”太困难，为什么不先构造较简单的初始程序，再研究怎样教它？他把初始结构、教育和其他经历分开，认为初始程序与教学过程都要试验、修订。他甚至明确保留两种候选：机器可以从较少内置结构出发，也可以预先装入相当多的逻辑推理规则。这里没有一条后来感知机或语言模型的现成训练公式，却已经问出了本章的核心分工：程序可以预先规定**怎样根据经历改变**，具体的判断规则仍可以随经历而变。([Turing，1950，第 7 节“Learning Machines”](https://academic.oup.com/mind/article/LIX/236/433/986238))

<a id="history-1950"></a>
同在 1950 年，Claude Shannon 给出了更具体的计算机下棋方案。机器先得懂棋规，从一个局面列出合法走法，再向前搜索。棋局分支太多，不能每次把整盘棋算到终点，所以必须在尚未结束的局面停下，用棋子、位置、活动余地等线索估计局面好坏。这样的程序即使评分由人写定，仍可以认真地下棋；“没训练过”不等于“只会乱走”。这也说明 Turing 所说的“教育”并非一切聪明程序的强制条件：研究者还可以先把规则和搜索做好。Shannon 的论文研究的是如何编出可用的下棋程序，不应把后来常见的参数训练倒填进去。([Shannon，1950，第 1、3 节](https://d1yx3ys82bpsa0.cloudfront.net/chess/programming-a-computer-for-playing-chess.shannon.062303002.pdf))

<a id="history-1952"></a>
这条棋类路线随后有了实际运行的程序。Arthur Samuel 在 1959 年论文的脚注里回顾：IBM 701 上能运行的跳棋程序写于 1952 年，1954 年改写给 IBM 704。要让程序合法地下棋，得实现棋规、输入输出和搜索；在搜索停下的地方，还得有办法估计局面。即使此时不学习，基础程序也能下出有内容的棋。把这种已有能力略去，接着把“会学习”说成机器第一次会下棋，会误解后来的研究起点。([Samuel，1959，第 212 页与脚注 3](https://gwern.net/doc/reinforcement-learning/model-free/1959-samuel.pdf))

<a id="history-1955-dartmouth"></a>
1955 年提交的 Dartmouth 夏季研究提案、1956 年举行的研究项目，也让我们看见当时的问题远不止“找一种会学习的网络”。提案把语言、抽象、解决问题和自我改进并列，还讨论计算机的速度与容量，以及如何把已有程序能力真正用起来。它记录了一群研究者要探索的范围，并没有给出一条所有机器都必须走的训练流水线；我们也没有证据说 Samuel 的某项跳棋设计是受这份提案直接指挥的。([McCarthy、Minsky、Rochester 与 Shannon，1955 年提案](https://www-formal.stanford.edu/jmc/history/dartmouth/dartmouth.html))

<a id="history-1955-samuel"></a>
Samuel 的第一个带学习功能的跳棋版本也在 1955 年完成，并于 1956 年展示。这一步在原有下棋程序之外增添了新问题：过去的棋局留下什么，下一次搜索如何使用，判断调整有效的依据又从哪里来。1959 年论文汇总的是此后一段研究，不意味着论文里每一种改进在 1955 年的展示版中就已齐备。([Samuel，1959，脚注 3 及第 215—219 页](https://gwern.net/doc/reinforcement-learning/model-free/1959-samuel.pdf))

<a id="history-1956-logic"></a>
同一时期还有一条值得认真对待的路。Allen Newell、J. C. Shaw 和 Herbert Simon 的逻辑理论机，用已经给定的公理和推理规则寻找证明：例如已知 \(P\) 及“若 \(P\) 则 \(Q\)”，就允许推出 \(Q\)。规则本身只说哪一步合法，不能告诉程序在许多可能的步骤中先试哪条路；他们研究的正是怎样用启发式选择，让搜索在可用时间里找到证明。1956 年已有论文说明程序，1957 年的实验论文展示了它在 JOHNNIAC 上运行和研究的过程。这里有实在的问题求解能力，研究重点却不是让七张标签卡片修改一组权重。若我们把“AI 的开端”压成一条通往可训练神经网络的路，这项工作就会无端消失。([Newell 与 Simon，1956 年论文档案](https://digitalcollections.library.cmu.edu/node/19110)；[Newell、Shaw 与 Simon，1957 年实验论文，第 218—220 页](https://iiif.library.cmu.edu/file/Newell_box00028_fld01976_doc0005/Newell_box00028_fld01976_doc0005.pdf))

<a id="history-1957-rosenblatt"></a>
1957 年，Frank Rosenblatt 已用《The Perceptron》报告提出研究方案；1958 年的论文把问题说得很清楚：外界信息怎样被感知，记忆以什么形式留下，留下的信息又怎样影响下一次辨认。他的感知机包含感受输入的部分、相互连接的中间单元和作出反应的部分，讨论连接随经验或反馈变化。它来自知觉与记忆研究，不能说成 Samuel 的跳棋程序遇到失败后“自然出现”的修补。我们下面要算的只是一个可以手算的单层版本，也不是当年装置的逐项复刻。([Rosenblatt，1957 年报告](https://bpb-us-e2.wpmucdn.com/websites.umass.edu/dist/a/27637/files/2016/03/rosenblatt-1957.pdf)；[1958 年论文，第 386—389、392 页](https://web.stanford.edu/class/psych209a/ReadingsByDate/01_30/Rosenblatt58Perceptron.pdf))

<a id="history-1959-samuel"></a>
Samuel 到 1959 年总结自己的跳棋实验时，把“记住具体局面”和“让少量评分项目概括许多局面”认真比较了。前者在一些开局和残局很有帮助，但存储与查找会越来越贵，中局仍有大量没见过的情形；后者改变评分项目的作用，在中局有长处，开局和某些残局又可能较弱。他还明确说，已有棋局不足以无歧义地证明调整已稳定，或找到了最好的系数。历史给我们的不是旧法被新法击败的庆祝词，而是一个可以继续研究的选择：经验可以作为具体记录留下，也可以改变许多输入共同使用的评分规则。([Samuel，1959，第 215—222 页](https://gwern.net/doc/reinforcement-learning/model-free/1959-samuel.pdf))

<a id="first-records"></a>
## 一张卡片、一份答案，以及一张会越存越大的表

为了把这项选择算清楚，我们暂时离开棋盘。下面七张二维点卡片由本书为教学而设计，每张有两个数值 \(x=(x_1,x_2)\)，另有事先指定的类别 \(y\)：

| \(x_1\) | \(x_2\) | 已给类别 \(y\) |
|---:|---:|:---:|
| 2 | 2 | \(+1\) |
| 1 | 3 | \(+1\) |
| 3 | 1 | \(+1\) |
| 0 | 0 | \(-1\) |
| 1 | 1 | \(-1\) |
| 2 | 0 | \(-1\) |
| 0 | 2 | \(-1\) |

这里的数和答案是**教学用的人工数据**。它们既不是 Rosenblatt 当年的视觉刺激，也不是 Samuel 的跳棋局面，更不是我们日后语言模型所需的真实语料。类别是事先指定的，程序只拿到这七对输入与答案。一个 \(x\) 连同它的 \(y\)，称为一条**带标签的样本**。以后若标签由标注者提供、从文本自动构造，或只在一次行动后才得到，学习问题就会改变，不能把这些来源混作同一件事。本例每条输入都有训练时可见的目标类别，属于**监督学习**；“监督”指这份目标信息，不是说运行时始终有人站在机器旁边。

先试最可靠的办法：把七条记录原样存下，遇到一模一样的 \(x\) 就返回已有答案。在 Python 里，`records` 是一张有顺序的列表；每一项如 `((2.0, 2.0), 1)`，前半是两项测量组成的元组，后半是标签。`for` 会逐项查看，`==` 比较两组数是否逐项相同：

```python
def lookup(examples, features):
    for saved_features, label in examples:
        if saved_features == features:
            return label
    return None
```

`def` 给这段操作取名；`return` 一旦找到匹配项就把答案交还调用者。若查完都没有，返回的 `None` 表示“表里不知道”，**不是**类别 \(-1\)。查表对七张旧卡片可以全对，还不需训练任何权重。如果下一张是 \((3,2)\)，表没有完全相同的记录，它就无法按这条办法答。点的取值一多，或测量可以取连续数值，精确匹配的机会就更少。这不使记忆法变坏：重复局面很多、必须保留特殊例外时，它可能恰好合适；这里只是要尝试另一种共享办法。

<a id="first-score"></a>
## 让几张卡片共用同一条分界线

观察这些点，正类都在右上方，负类靠左下方。我们可以为每张卡片算一个分数，而不为每个坐标位置另存答案。先让 \(x_1\) 与 \(x_2\) 各乘一个可调数，再加一个可调的常数：

\[
z(x)=w_1x_1+w_2x_2+b.
\]

把 \(z>0\) 判为 \(+1\)，其余判为 \(-1\)。这里 \(x_1,x_2\) 是这一次卡片的输入；\(z\) 是这一次计算出来的分数；\(w_1,w_2,b\) 才是下次还会沿用、可以由训练改变的**参数**。\(w_1\) 决定第一项测量增加 1 时分数怎样变，\(w_2\) 管第二项，\(b\) 决定整条分界线往哪里移。临时分数变了，只能说明输入或参数中至少有一方变了；要说“程序学了”，还得指出参数确实因训练记录而改变。

这是一种**线性分类器**：\(z=0\) 在纸上是一条直线，两侧给不同类别。在神经网络的入门语境中，用一个可调加权和接一个阈值判断，也常称**单层感知机**。这里的“层”说的是计算结构，不是训练了几轮；这个课堂形式省略了 Rosenblatt 原研究中的感受与关联单元。三个数共用一条规则，是它能对没见过的坐标给出答案的原因，也是它会受形状限制的原因。我们选择直线，是因为眼前点的位置使它值得一试，不是数学宣布所有分类都只能这样做。

把分数写成 Python 函数，正好能看到公式里的每个数是谁。`def` 后括号内的三个名字是调用时交给函数的对象，`return` 把算出的临时分数送回去；这里还没有改动参数。

```python
def score(weights, bias, features):
    return weights[0] * features[0] + weights[1] * features[1] + bias
```

例如 \(w_1=w_2=1, b=-3\) 给出的直线是 \(x_1+x_2=3\)。七张卡片里正类的和都是 4，负类的和不超过 2，因此这条线把它们完全分开。人已经能检查这个候选；问题转为程序能否只靠给出的卡片，逐次把一组初始参数改到可用的位置。

<a id="first-update"></a>
## “修正一下”到底改哪三个数

我们先把 \(w_1,w_2,b\) 全设为 0。训练时，若标签与分数落在同一侧，乘积 \(yz\) 为正；若判错或恰好压在分界线上，\(yz\leq 0\)。这让一条记录是否要求调整，可以只由它自己的标签和当前分数决定。标签 \(y\) 只取 \(+1\) 或 \(-1\)，所以改动方向可以写得很短：

\[
\begin{aligned}
w_1^{\text{新}}&=w_1+\eta yx_1,\\
w_2^{\text{新}}&=w_2+\eta yx_2,\\
b^{\text{新}}&=b+\eta y,
\end{aligned}
\qquad \text{仅在 }yz\leq0\text{ 时执行。}
\]

这里 \(\eta>0\) 是我们先选好的步长，不是从标签里算出的新量。为什么这样改值得试？如果一张正类卡片分数不够高，增加这张卡片激活的权重，能把它往正侧推；负类则向反方向推。偏置好像一直为 1 的第三项输入，故每次也沿 \(y\) 的方向改。把更新代回**同一张**卡片的分数，可得到

\[
y z_{\text{新}}
=y z_{\text{旧}}+\eta y^2(x_1^2+x_2^2+1)
=y z_{\text{旧}}+\eta(x_1^2+x_2^2+1).
\]

后面一项严格为正。因此，这一步总会改善当前卡片的“处在正确一侧的程度”，即 \(yz\)。这不是说它必能一步把卡片判对，更不保证别的卡片也改善：它们共用这三个数，改动会同时影响所有输入。这个更新没有求平方误差的导数；它只利用类别和分数的符号。下一主题才研究保留分数大小、按连续误差调整时会得到什么不同的信息。

手算第一步。首张卡片是 \(x=(2,2),y=+1\)，零参数给 \(z=0\)，取 \(\eta=1\)。更新后 \(w=(2,2),b=1\)，它自己的新分数成为 \(2\times2+2\times2+1=9\)。这个 9 不是“有 90% 把握”，只是未校准的分数；而且很大的第一步会影响随后所有卡片。轮到负类 \(x=(0,0)\) 时，当前分数为 1。它的两项输入都为 0，改动权重不起作用，偏置从 1 改为 0，分数到达边界。再遇到负类 \(x=(1,1)\)，旧分数为 4，更新后权重变为 \((1,1)\)、偏置为 \(-1\)，新分数仍是 1，仍在错误侧，只是 \(yz\) 从 \(-4\) 提升到 \(-1\)。这几个数正好说明了“修正”的实际含义，也说明一次改动并不等于已经学会。

<a id="first-code"></a>
## 让 Python 按刚才的账目执行

下面是[完整可运行程序](../code/first_perceptron.py)中改变参数的部分。`weights` 是两个会被保存的权重，`bias` 是第三个参数。`score(...)` 每次读取一张卡片和当前参数，返回临时分数。外层 `for` 表示反复看整批记录；内层 `for` 才是一张接一张地处理。`+=` 会修改左边那个数，并非给标签改答案。

```python
weights = [0.0, 0.0]
bias = 0.0
for epoch in range(1, max_epochs + 1):
    updates = 0
    for features, label in records:
        old_score = score(weights, bias, features)
        if label * old_score <= 0:
            weights[0] += learning_rate * label * features[0]
            weights[1] += learning_rate * label * features[1]
            bias += learning_rate * label
            updates += 1
    if updates == 0:
        break
```

`features[0]` 是本张卡片的第一项测量，`features[1]` 是第二项；Python 从 0 开始编号。`range(1, max_epochs + 1)` 给出最多允许的轮次，`break` 在一整轮没有改动时结束循环。这个上限是程序防止无止境运行的措施，不是“练习两百轮一定会学会”的保证。完整代码还记录每轮更新次数、最初几次参数变化，并在写入文件后重新读取学到的数。

在本项目根目录的 PowerShell 终端执行：

```powershell
$env:PYTHONUTF8='1'
python work/code/first_perceptron.py
```

<a id="first-experiment"></a>
本机这次运行每轮分别更新了 **5、2、2、0** 次，最后一轮没有更新。程序得到 \(w=(1,1),b=-3\)，正是前面已手工检查过的分界线。七张训练卡片的分数分别是 \(1,1,1,-3,-1,-1,-1\)，类别均相符；旧表没有答案的 \((3,2)\) 和 \((0,1)\)，这条线分别给出分数 2 和 \(-2\)。[完整运行记录](../results/first_perceptron_run.json)保存了逐项数值。这里没有随机抽样或隐藏库调用；改变记录顺序、标签或步长会改变训练经过的路径，有时也会改变最终参数。

<a id="first-storage"></a>
参数随后写到 [JSON 文件](../results/first_perceptron_model.json)，再读回来并核对两个权重和偏置。JSON 是一种能保存列表、数值等基本数据的文本格式；`json.dumps(...)` 把当前 Python 对象写成文字，`json.loads(...)` 把文字读回。程序文件保存的是**怎样计算和更新**，JSON 文件保存的是**这次训练结束后得到的数**。关掉程序再打开，只执行前者而不读后者，就会从零参数重新开始。这一处小小的文件交接，正是训练状态与运行一次时的临时分数之间的区别。

完整程序开头的 `import json` 和 `from pathlib import Path` 是从 Python 标准库取来处理 JSON 和文件路径的工具；`Path(__file__)` 从程序自身的位置寻找 `work/`，所以从项目根目录运行时不用手工填写一条带用户名的绝对路径。写出模型的核心两行实际是：

```python
model_path.write_text(
    json.dumps({"weights": weights, "bias": bias}, ensure_ascii=False, indent=2),
    encoding="utf-8",
)
restored = json.loads(model_path.read_text(encoding="utf-8"))
```

花括号把两个有名字的值组成字典；`encoding="utf-8"` 约定文件中文字怎样编码。重新读回的 `restored` 若没有与内存中的参数相等，程序的 `assert` 会让运行停下并报错，而不是悄悄把保存失败当作成功。

<a id="first-system"></a>
现在可以用刚做过的事区分几层常被混叫“模型”的对象。**任务**是给点卡片分两类；七条带标签的记录是这次的**训练数据**。计算分数和作出判断的三个参数构成当前**模型**，其中一个加权单元是极简的神经网络；`for` 循环与更新条件是**训练方法**。Python 解释器运行这些语句、从磁盘读写文件，属于模型外面的执行环境，今后讨论工具时会把这类程序称为**宿主**。只把代码中的 `score` 函数保存下来并没有保存学到的参数；只留 JSON 数字而没有计算规则，也不能自行完成判断。

这样再回看 Turing 在 1950 年分开的“初始程序”和“教育过程”，它们不再只是好听的设想。在我们的微型例子中，`score`、更新条件和循环是人事先编好的；三项参数的**训练后数值**却由那七条记录决定。机器没有在训练时发明 Python 代码，也不只是机械地把七个答案复制进参数文件。下一次输入来到时，三个共享的数和同一段计算一起产生判断。这不等于说 Turing 设计过这七张卡片，而是用已做成的计算辨认他当时提出的两种责任。

<a id="first-proof"></a>
## 为什么这批点有机会在有限步后停下

一次更新只照顾当前卡片，为什么这次循环会真的停？先检查一个条件，而不是从结果倒推“总会成功”。给每张卡片在末尾补一个恒等于 1 的坐标，写成 \(\tilde x=(x_1,x_2,1)\)，把三个参数合写为 \(v=(w_1,w_2,b)\)。刚才的更新便是 \(v\leftarrow v+y\tilde x\)，这里步长为 1。

对本章七张卡片，向量 \(u=(1,1,-3)\) 已由表格直接验证满足 \(y(u\cdot\tilde x)\geq1\)：正类给 1，负类至少也给 1。我们把“所有训练点都在正确侧，且离边界有正余量”叫作这批点在所选表示下**线性可分**。这是关于数据与表示的条件，不是关于程序写得漂亮的评价。

设程序已经做了 \(M\) 次更新。每次沿 \(y\tilde x\) 走，和 \(u\) 的内积至少增加 1，起点又是零，所以 \(u\cdot v_M\geq M\)。另一方面，每次只在 \(y(v\cdot\tilde x)\leq0\) 时更新，于是

\[
\|v+y\tilde x\|^2
=\|v\|^2+2y(v\cdot\tilde x)+\|\tilde x\|^2
\leq\|v\|^2+\|\tilde x\|^2.
\]

七张卡片里最大的 \(\|\tilde x\|^2\) 是 \(11\)，故 \(\|v_M\|^2\leq11M\)。再用高等代数中熟悉的柯西—施瓦茨不等式，\(M\leq u\cdot v_M\leq\|u\|\|v_M\|\leq\sqrt{11}\sqrt{11M}\)。因为 \(\|u\|^2=11\)，只要 \(M>0\)，两边平方并约去一个 \(M\)，就有 \(M\leq121\)。这个界很宽：实际只用了 9 次更新；它也只回答这批点为什么有条件在有限步内停，不证明训练结果能代表真实世界。

把具体数字移开，才能看出证明真正依赖什么。设另一批增广输入的长度都不超过 \(R\)，并且存在某个向量 \(u\)，使每条卡片满足 \(y_i(u\cdot\tilde x_i)\geq\delta>0\)。\(\delta\) 是它们相对这条候选分界的最小**有符号余量**：越接近零，至少有一张卡片越贴近边界。沿用刚才两笔账，\(M\) 次更新一方面使 \(u\cdot v_M\geq M\delta\)，另一方面使 \(\|v_M\|\leq R\sqrt M\)。于是

\[
M\delta\leq\|u\|R\sqrt M
\quad\Longrightarrow\quad
M\leq\left(\frac{R\|u\|}{\delta}\right)^2.
\]

本章的 \(R=\sqrt{11}\)、\(\|u\|=\sqrt{11}\)、\(\delta=1\)，正好回到 121。这个一般式告诉我们：有限停止并非“训练 200 轮”的魔法，而依赖于输入长度有界，以及确实存在一条带正余量的分界。若找不到这样的 \(u\)，这段证明便不能使用；单凭证明失效，也不能反过来断言每种程序都不会停。这里是课堂上的向量证明，与 1962 年 Novikoff 对感知机收敛给出的简洁证明属于同一思路；它不是 Rosenblatt 1957 年报告中的七张点卡片实验。([Novikoff，1962，《On Convergence Proofs for Perceptrons》，印刷页 615—618](https://cs.uwaterloo.ca/~y328yu/classics/novikoff.pdf))

还有一个可以直接预测程序结果的细节。若从零参数开始，把每次更新的固定正步长从 1 换成 \(\eta\)，每一步得到的参数都会是步长为 1 时相应参数的 \(\eta\) 倍；判定是否更新只看 \(yz\) 的正负，所以卡片顺序与更新位置不变。上面的两笔不等式分别多出 \(\eta\) 与 \(\eta^2\)，最后的次数界也不变。这依赖零初值、固定正步长和只看符号的更新条件；换成下一章的连续误差目标，不能照搬。

<a id="first-variation"></a>
现在用程序改条件，而不覆盖第二章要读取的默认模型。在项目根目录依次运行：

```powershell
python work/code/first_perceptron.py --rate 0.5
python work/code/first_perceptron.py --case omit-origin
python work/code/first_perceptron.py --case midpoint-conflict --max-epochs 30
```

第一条得到的更新次数仍为 \(5,2,2,0\)，参数成为 \((0.5,0.5,-1.5)\)，正好验证刚才的缩放论证。第二条删去 \((0,0)\) 后，更新次数由 9 变为 22，最后为 \((2,2,-6)\)：即使没有那张全零测量卡片，其他记录触发更新时，偏置仍会改。尤其要注意，删去一条卡片不是从旧训练过程抹掉它那一次更新就结束了；后续每张卡片看到的参数已不同，整条轨迹会重排。第三条把 \((1,1)\) 的类别改成正类；三十轮结束时仍有更新。运行记录分别写到带 `probe` 的独立 JSON 文件，默认运行生成的 [模型文件](../results/first_perceptron_model.json)保持原路径，第二章因而仍能读取原来的七张卡片训练结果。

第三条的运行现象还不能证明“再训练多久也不行”。要作这种断言，需要检验所要求的分界是否存在，而这正是下一节的工作。

<a id="first-limits"></a>
## 成绩的边界，正好告诉我们下一步该问什么

先看表达能力的边界。若四张卡片的标签改成：\((0,0)\) 与 \((1,1)\) 为负，\((1,0)\) 与 \((0,1)\) 为正，那么无论 \(w_1,w_2,b\) 怎样选，一条直线都分不开它们。正类要求 \(b+w_1>0, b+w_2>0\)；负类要求 \(b\leq0, b+w_1+w_2\leq0\)。前两式相加说明 \(2b+w_1+w_2>0\)，后两式相加却说明同一个数不大于 0。矛盾来自我们选的**线性分数族**，不是说计算机根本不能学会这四张卡片；换表示、查表或使用更复杂的网络，问题都会改变。

再看证据的边界。本章新增的两张卡片虽然没放进训练表，却仍按我们预先设计的同一条简单分界线挑选，不能拿它们的两个正确答案宣称自然数据上的泛化能力。真实任务中，测量可能有噪声，标签可能由人产生分歧，先写下的训练条件也可能错。要判断一个方法在新的记录上是否可靠，今后必须认真设计数据来源和留出的评价。眼前的实验只证明更有限而清楚的事：这段代码确实把七条标签中的信息变成了三个共享参数，存盘后也能重新用于预测。

这一章里，规则、经验和程序的分工已经落地：人指定了输入、标签和更新方法；机器用这些记录改变 \(w_1,w_2,b\)；预测时的输入改变分数，却不再自动修改参数。下一章接着追问一个新的问题：如果两个模型都判错了，其中一个分数只差一点，另一个差得很多，训练时要不要利用这份连续差距？要回答它，我们会先选一个明确的误差尺度，再研究这个尺度怎样决定改权方向，而不是把“用梯度”当作无来由的口令。

<a id="first-exercises"></a>
## 动手检查

1. 对照第二条变体运行，解释为什么删去 \((0,0)\) 后，偏置仍改变，而且总更新次数不是“原来九次减去这张卡片触发的次数”。从程序里找出第一轮其他卡片怎样改偏置。
2. 暂不运行，先预测把步长改为 `2.0` 时，每轮更新次数与最后三个参数；再运行 `python work/code/first_perceptron.py --rate 2`。本章的有限更新次数证明为何没有因步长加倍而失效？
3. 把 \((1,1)\) 的标签改成 \(+1\)，同时保留 \((2,0)\)、\((0,2)\) 为 \(-1\)。比较 `--case midpoint-conflict --max-epochs 30` 与把轮数改成 200 的结果。哪一项证据说明“这两种设置里都没有停”，哪一项才证明“一条直线根本无法同时满足这些标签”？

**核对与解析。**第一题中，只要另一张卡片触发更新，偏置就沿其标签方向改，因为它相当于一个恒为 1 的输入。删掉原点后，后续卡片碰到的参数不同，因而触发更新的次数与原过程不必只差原点所贡献的次数；这次实跑从 9 次变成 22 次。第二题仍是每轮 \(5,2,2,0\) 次更新，最后 \(w=(2,2),b=-6\)。对同一旧参数的每次更新，多出的步长系数在有符号分数里保持正比例；在收敛证明中，方向进展乘 2，长度上界也乘 2，两者相约后次数界不变。第三题的两次运行只表明在各自轮数预算内都没出现无更新的一轮。更强的结论来自几何：\((1,1)\) 恰好是 \((2,0)\) 与 \((0,2)\) 的中点；任何仿射分数在中点的值等于两端分数的平均。若两端都必须不大于 0，中点不可能大于 0。因此这组标签无法由本章的直线同时满足，和你愿意多跑多少轮无关。
