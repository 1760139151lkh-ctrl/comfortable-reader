# 第三十三章　视频不只是许多图片

上一章听到的声音是一串有先后的采样。把同一批数倒着播放，字词和事件可能变得难以辨认；这个改变不在单个采样点里，而在它与别的点之间的关系里。视频也有这样的时间关系，但每一时刻交给我们的不是一个声压数，而是一整张图。第十三章教过怎样用共享的小权重表找图里的局部形状，第十四章教过怎样把过去的信息留给后一步。把两章的程序接上，仍有三个问题要亲自回答：哪一部分画面真的在移动？一整段到底是什么动作？如果画面还没有拍到，模型能够产生怎样的下一帧？

先看[本机保存的一段真实投球视频](../videos/c33_penn_pitch_0002_10fps.mp4)。它来自 Penn Action 原始帧；为了方便观看，我们把八十张按顺序以每秒十张**回放**。原资料没有可供本书可靠换算的逐帧真实秒数，所以播放器显示八秒，不是这次投球在现实里持续八秒。[下面这张并排图](../figures/c33_same_current_opposite_motion.png)从同段视频取第31、36、41帧。右列的两张“当前第36帧”是**同一个原图文件**；左上第31帧接它，腕部标注的横坐标从约72.7到90，向画面右侧；左下先给第41帧再给同一第36帧，横坐标从约130.7到90，向画面左侧。第二项是把真实后来的帧放在前面形成的**倒序观察**，不是声称投手在原视频中突然向左做了一次相反动作。恰恰因为当前图完全一样，问题才清楚：只看当前，不能分辨这两条输入的方向；给它一张有关系的另一帧，才有可用证据。

<a id="thirtythird-frame-object"></a>
## 一段视频究竟给了模型什么

把按顺序取得的画面记作 \(I_0,I_1,\ldots,I_{T-1}\)。每张 \(I_t\) 是高、宽、颜色三轴上的数字表；\(t\) 在本章 Penn 数据里首先是**帧序号**。若拍摄时有可信时间戳 \(\tau_t\)，才可以进一步问隔了多少秒。相同的五帧序号间隔，在不同帧率或丢帧的视频中未必代表同样时长。因此本章算腕部在图像平面移动了多少像素、隔了几帧，不从中硬算米每秒或真实挥臂加速度。

“看视频”还不是一项训练任务。给一段 \(I_{0:T-1}\) 和整段动作名 \(y\)，可以学 \(p_\theta(y\mid I_{0:T-1})\)，回答发生的是投球、跳绳还是别的活动。给起点位置和连续帧，可以追问下一帧同一处图案在哪里，这是**跟踪**。给过去帧并要求一张尚未见的未来图，则是预测或生成；若还给文字、人的控制动作或另一幅结尾画面，条件和可检验的回答又不同。一个整段“投球”标签不标出球何时离手，也不直接告诉网络每一帧的右腕位置；反过来，知道一个腕点的位置也不足以给所有人的动作分类。

对本书的实验，我们使用[宾夕法尼亚大学公布的 Penn Action](../data/penn_action_original/SOURCE.md)。2013年论文研究真实消费视频中的人类动作，原件有2326段、15个整段动作类，以及每帧13个关节的二维位置和可见性；论文说明每段的关节点由三份人工标注合成。这样的资料让我们能分别检查“动作名从哪里来”和“画面里的手腕到底往哪里去”，无需假装网页上有人为每一像素写了解说。官方标记中1258段用于训练、1068段用于测试。作者在训练组内部再按视频编号留出验证；原始较长视频在这个内部划分里是否也完全分开，现有元数据不足以证明。我们保留官方测试组做组外检查；其源文件后来被本章不同实验相继使用，后面的成绩会逐一说明测试身份。原网站和归档没有查到明确的图像再发布许可，所以本地可以读这些链接和运行实验；若把带原帧的书稿对外发行，需另行核权。([Penn Action 原论文，§4—5](https://dreamdragon.github.io/papers/iccv13_acteme.pdf))

把一段视频变成八张训练图时，我们从首帧到末帧按**序号**等距选取，保留纵横比并补黑边到90×160。这样一个短片即使有上百原帧也能交给小网络，但急促的动作可能正好落在未选中的间隙。更密地抽帧会花更多计算，也未必增加独立信息；若物体在两次采样之间来回到了同一位置，单靠首尾图甚至看不出它动过。后文的“八帧”因此是一个明说的观察条件，不是视频本身只有八个时刻。

<a id="thirtythird-history-motion"></a>
## 从把动作分解成照片，到要求机器算运动

1878年，Muybridge的连续赛马照片使一连串姿势可供逐张检视；所问的是快到肉眼难以停住的马蹄在奔跑时怎样着地。随后连续摄影与放映设备改变了记录和观看方式：美国国会图书馆的早期电影时间线记载，Marey 1882年的设备可连续摄得十二幅；1895年 Lumière 兄弟把影像公开放映到银幕上。拍下和放映运动还不是机器识别动作；两者共同留下的是一个可再问的对象——相邻画面有可计算的变化。([国会图书馆藏 Muybridge 原件目录](https://www.loc.gov/item/2005684184/)；[国会图书馆早期电影时间线](https://guides.loc.gov/chronicling-america-early-cinema))

这个问题也从人的知觉一侧受到检验。Johansson在1973年的论文中，把人体主要关节的活动表示为少数移动亮点：没有完整衣服和脸部轮廓，合适的十余个亮点组合仍能使观察者看出走、跑、跳舞。我们这里只依据论文可见的摘要作这层判断，不用它宣称人脑按某个现成视频网络算光流。它提醒模型设计者：单张图上的“是什么形状”，与亮点**怎样随时间共同变化**，提供的信息不同。我们下面使用的 Penn 人工关节点是2013年的另一项资料工作，绝不能说1973年实验已经给它提供训练标签。([Johansson，1973，原刊摘要](https://link.springer.com/article/10.3758/BF03212378))

到1981年，计算机视觉研究者面对的是更直接的计算难题：两张图中哪处对应哪处？Lucas与Kanade在图像配准和立体视觉任务里寻求快速办法；Horn与Schunck则明确问怎样从连续图像估计**光流**，也就是亮度图案在画面坐标中的表观移动。后来的动作识别系统会把这种低层运动线索与外观一起用，但1981年两篇论文不以 Penn 视频、文字生视频或现代助手为目标。我们先亲手把光流式子推出来，才知道本机跟踪程序究竟补了什么假设。([Lucas与Kanade，1981，§2](https://publications.ri.cmu.edu/storage/publications/pub_files/pub3/lucas_bruce_d_1981_1/lucas_bruce_d_1981_1.pdf)；[Horn与Schunck，1981，§2—5](https://people.csail.mit.edu/bkph/papers/Optical_Flow_OPT.pdf))

<a id="thirtythird-flow-equation"></a>
## 一张图上的亮度变化，能推出二维位移吗

暂把一帧灰度图的亮度写为 \(I(x,y,t)\)。若同一小块表面在短时间 \(\Delta t\) 内从 \((x,y)\) 移到 \((x+u\Delta t,y+v\Delta t)\)，并且它的亮度近似不变，就有

\[
I(x+u\Delta t,y+v\Delta t,t+\Delta t)\approx I(x,y,t).
\]

这里 \(u,v\) 是**画面坐标**每单位时间的水平、垂直变化率；在只有等间隔帧序而无真实秒数时，我们只能把单位取成帧间隔。对左边在 \((x,y,t)\) 作一阶展开，减去右边，再除以 \(\Delta t\)，得到

\[
I_xu+I_yv+I_t\approx0.
\]

三个偏导分别衡量亮度沿水平、垂直和时间的局部变化。这个式子来自**短位移、局部可微和亮度近似保持**；有遮挡、新光源或镜面高光时，它可不合适。更关键的是，它只有一条等式，却要决定 \(u,v\) 两个未知数。想象一条竖直边，亮度主要沿水平方向变，\(I_y\) 接近零：沿边往上或往下挪，单点亮度看起来都差不多。数学上此时只能约束 \(I_xu\)，无法由这一点唯一算出 \(v\)。这叫**孔径问题**；网络再大也不能从没有区分力的单个局部方程凭空取得第二条独立信息。

一个可行的附加选择是：在很小的邻域 \(W\) 里，先把这块图案看成近似同一个平移 \((u,v)\)，合并多点的约束。若第 \(k\) 点给出 \((I_{x,k},I_{y,k},I_{t,k})\)，就最小化

\[
E(u,v)=\sum_{k\in W}(I_{x,k}u+I_{y,k}v+I_{t,k})^2.
\]

把各点的两项空间梯度排成矩阵 \(A\)，把时间梯度的负数排成向量 \(b\)，这就是 \(\min_{(u,v)}\|A(u,v)^\top-b\|^2\)。对两个未知数求导，得到 \(A^\top A(u,v)^\top=A^\top b\)。只有邻域里存在足够不同方向的亮度变化、\(A^\top A\) 才有良好条件来区分两个方向。纯粹的竖边重复再多次，依旧不能补出垂直信息；窗太大或物体边界跨窗，又会破坏“同一个平移”。Lucas—Kanade一类局部方法在这样的取舍上工作。另一条路线像Horn—Schunck原论文那样，在整个画面的位移场上增加空间平滑条件；平滑也属于**额外建模决定**，不是亮度式本身证明了相邻物体一定同速。

<a id="thirtythird-tracking"></a>
## 跟着一个点走，和自己找出手腕不是同一件事

我们在 Penn 官方训练组的一段投球里，取第31帧人工标出的右腕位置作**唯一初值**；之后用 OpenCV 的金字塔 Lucas—Kanade 跟踪至第49帧，直到评价时才用后续人工点检查。金字塔先在较粗图上找位移，再逐层细化，让原图里较大的移动不全压在一个小窗里。[横坐标与二维误差图](../figures/c33_lk_wrist_one_video.png)同时画了人工点、算法跟踪点和“始终停在第一帧坐标”的基线。后续可见点的平均二维误差，跟踪约31.1像素，固定点约63.2像素；算法确实从相邻图案取到了信息，却在运动较快和姿势改变处偏离了人的腕部位置。这只是一段事先挑出的训练视频，不是一个无需人给初值就能找到任何人右腕的检测器，更不是三维身体速度。读者可直接检查[跟踪程序](../code/c33_track_wrist_probe.py)怎样只初始化一次，以及[逐帧数值](../results/c33_lk_wrist_one_video.json)怎样与图相应。

画面中的纹理移动还可能来自摄影机：拍摄者左右转动，静止看台也会在图里横移。2013年Wang和Schmid在动作识别中估计并剔除与相机一致的轨迹，正是因为“很多像素在动”不足以说“人做了什么”。本章的腕坐标是**图像平面坐标**；若相机跟着投手移动，右腕像素坐标的差也会被相机投影改变。下一章要把相机、三维点和像素联系起来，才能认真问现实空间里谁相对谁移动。([Wang与Schmid，2013，摘要与方法](https://openaccess.thecvf.com/content_iccv_2013/papers/Wang_Action_Recognition_with_2013_ICCV_paper.pdf))

<a id="thirtythird-paired-direction"></a>
## 让“只看当前帧”真正无路可走

现在可以把开头两对真实画面变成一项有精确对照的小学习任务。Penn 的人工右腕点只用来**制成和核对标签**：先筛选同一真实视频里 \(t-5,t,t+5\) 三帧的手腕都可见，并且两段正向原视频移动都朝同一水平侧、各自至少跨原画宽的2%。对每个中心造两个输入：\((I_{t-5},I_t)\) 按正向帧序，\((I_{t+5},I_t)\) 按倒序帧序；第二项被标为相反的**画面水平位移符号**。后者并非 Penn 原始的“投球”动作标签，也不说现实的动作突然逆转。网络只收到两张原 RGB 图和两图像素之差，完全收不到人工腕点坐标、框或动作名。

设单帧规则只以最后一张 \(I_t\) 输出类别 \(f(I_t)\)。每个中心的两个输入末帧逐字节相同、正确方向却一左一右；无论 \(f\) 在这张图上答左还是答右，两条中恰好只对一条。把全部中心配对平均，**任何确定的只看当前帧规则严格得50%**；随机规则在期望上也只有50%。这是对本书这一道派生题的证明，不是说所有现实动作仅看一帧都最多50%——有些动作会留下足以识别的姿势或器具。第十四章的末八步线索例子同样区分“输入本来不给信息”和“给了信息却没学会”；这里用真实图像把那一区别落到视频上。

把两张90×160的 RGB 图及差图并为九通道，随机初始化的小卷积网络输出左右两路分数，再用第十三章十类训练处已教过的分数归一化与交叉熵，让真实标签提高概率。程序里这一计算可以只看几行：

~~~python
triplet_ids = pair_ids // 2
side = pair_ids % 2
first_indexes = np.where(side == 0, 0, 2)
first = np.asarray(triplets[triplet_ids, first_indexes], dtype=np.float32) / 255.0
current = np.asarray(triplets[triplet_ids, 1], dtype=np.float32) / 255.0
delta = current - first
input_array = np.concatenate([first, current, delta], axis=-1)
x = torch.from_numpy(input_array.transpose(0, 3, 1, 2).copy()).to(device)
y = torch.from_numpy((signs[triplet_ids] ^ side).astype(np.int64)).to(device)
logits = model(x)
loss = F.cross_entropy(logits, y)
optimizer.zero_grad(set_to_none=True)
loss.backward()                 # 计算参数梯度
optimizer.step()                # 才把梯度写进权重
~~~

这是实际[训练源码](../code/c33_real_motion_direction.py)里整理到一起的几段：`pair_ids // 2` 找回属于哪组三帧，`pair_ids % 2` 决定拿较早还是较晚的帧放在输入首位；`signs` 的0/1先记正向原视频的水平符号，`^ side` 在倒序那项翻转答案。`np.concatenate` 在末轴把三张 RGB 图合成九通道，`transpose` 则把它换成 PyTorch 所需的“批次、通道、高、宽”顺序。完整可直接运行的程序仍在链接里；它把左右翻转作为训练增广时，还要同时交换“左/右”标签，不能只翻图不改答案。差图没有额外标签，它由两张已给的帧相减而来；`backward()`仍只求导，`step()`才改变参数。

官方训练组里符合这一事先条件的有460段视频；按视频编号分成368段调参数、92段选轮次，得到1206和315个三帧中心。三十轮里选内部验证交叉熵最低的第18轮，小网络在内部630个成对输入答对477个。固定模型后**第一次为这道方向题**打开官方测试标记的1068段，只有370段达到可见性和位移门槛，形成1228个中心、2456个配对输入；答对1821个，约74.1%。从50%到74.1%说明这道筛过的题里，两张真实帧给网络提供了单张当前帧没有的可学证据；它没证明腕部被准确定位，也没覆盖其余698段不合筛选的视频。按视频先各自算正确率再平均约70.7%，比把片段一股脑平均低，提醒我们多片段视频权重不同；跳跃开合可用片段约48.6%，仰卧起坐约94.9%，失败和成功并存。[源数据与筛选清单](../data/penn_action_original/motion_gap5_v1/manifest.json)、[训练程序](../code/c33_real_motion_direction.py)和[固定模型的组外结果](../results/c33_real_motion_first_official_test.json)保留了每项身份。

<a id="thirtythird-action-history"></a>
## 方向以外，还有“这整段在做什么”

跟住图案或判断一个腕点的左右位移，并不能直接说“这是投球”。同样的手臂轨迹可能属于投掷、挥拍或招手，背景中的球场与器具也会改变分类器的猜测。为了先把光流和本机方向题算完，我们刚才谈到2013年的相机补偿和 Penn 资料；现在回到**整段动作识别**这条线，看它在那以前怎样寻找可比较的表示。Bobick与Davis在2001年把视频中哪里发生过运动、运动距当前有多近压成时间模板，再对人的操练动作作匹配；原视频虽是一张张画面，模板保存的不是无序照片集合。Laptev与Lindeberg在2003年研究时空局部显著点，2004年Schüldt等把这样的局部时空线索与第七章学过的支持向量机结合，并公开多人多场景动作资料。这些是在深卷积网络成为主流候选以前认真处理“局部变化怎样进入整段识别”的路线，不应因今天能写 `Conv3d` 就把它们删成空白年代。([Bobick与Davis，2001，摘要/§1](https://www.cs.bu.edu/faculty/betke/cs591/papers/bobick-davis.pdf)；[Laptev与Lindeberg，2003，摘要/引言](https://citeseerx.ist.psu.edu/document?doi=fc290c9840444d07bf253c2b35f7a65e717be612&repid=rep1&type=pdf)；[Schüldt等，2004，摘要/引言](https://faculty.cc.gatech.edu/~hic/CS7616/Papers/Schuldt-et-al-2004.pdf))

2013年的 Penn Action 同时给整段动作类与每帧人体点，目的之一正是让“视频里什么时候、什么地方发生什么”有更明确的检验。同期 Wang 与 Schmid 的相机运动补偿，又提醒所有跟踪轨迹都不能直接当人体行动。此时并没有一条唯一正确的“视频网络”路线：你可以测局部运动，也可以跟轨迹，也可以利用人体点，还可以让卷积从 RGB 图里学。各方案所需的标注、相机假设和计算量不同。我们的右腕小实验使用了 Penn 人工点**定义一道额外方向题**，不是该论文官方15类动作成绩；现在把资料恢复到原有的整段类任务，看看模型会学到什么。([Penn Action，2013，§4—5](https://dreamdragon.github.io/papers/iccv13_acteme.pdf)；[改进轨迹，2013](https://openaccess.thecvf.com/content_iccv_2013/papers/Wang_Action_Recognition_with_2013_ICCV_paper.pdf))

<a id="thirtythird-three-encoders"></a>
## 一帧、八帧无序平均、八帧按顺序读

令第十三章式的图像编码器 \(f_\theta\) 把一帧变成128个特征数，\(h_i=f_\theta(I_{t_i})\)。我们实际从每条 Penn 官方训练视频均匀取八张，训练三支**各自从随机权重开始**的小模型。

第一支只取八张中的第五张 \(h_5\)，接十五路分类头。它看不到前后次序，是场景和一瞬姿势能做到什么的实测参照。第二支把全部八个向量平均：\(\bar h=\frac18\sum_{i=1}^{8}h_i\)，再接同型分类头。它知道出现过哪些可由帧编码出的特征，但交换任意两帧，平均完全不变。若标签必须分清“放下”与“拿起”，恰好两组图在逆序时仍会得到同一个 \(\bar h\)，这种表示**在定义上**不可能把它们分开。第三支保留 \((h_1,\ldots,h_8)\) 的次序，用沿时间轴扫描的小卷积把相邻向量结合，再接分类头；它**有能力**对换序给不同输出，但有能力不等于有限资料会逼它学到该用法。三支的输出都是十五个分数，已知整段动作名 \(y\) 后训练负对数正确类概率：

\[
q_\theta(k\mid I_{t_1:t_8})=
\frac{\exp s_k}{\sum_{j=1}^{15}\exp s_j},
\qquad
L=-\log q_\theta(y\mid I_{t_1:t_8}).
\]

这仍是第十三章已经从分类分数推到梯度的目标。动作类由 Penn 原标注提供；图像编码器与分类头的参数由反传改变，逐帧人体点**没有**喂给这三支。两支多帧网络必须计算八次空间编码，时间卷积分支还多约23万参数，因此这里主要比较它们分别看见和丢掉什么信息，不伪装成严格同参数、同算力的算法排位赛。[实际模型源码](../code/c33_penn_action_models.py)的 `ActionModel.forward` 清楚标着输入五轴为“批次×8帧×3色×90高×160宽”；它先对每帧用同一个空间编码器，再在时间轴选择取第五、求均值或卷积。此处“时空卷积”的时间轴是相邻**帧特征**，不是下一章的世界三维坐标。

官方训练组1258段里我们按视频编号留1010段更新、248段选择。三支各训15轮，按各自验证交叉熵最低选第10、12、14轮，内部验证正确率依次约51.2%、60.5%、48.0%。若到这里就说“八帧无序已把动作识别解决了”，便忽略了第六章关于组外评价的教训。固定权重后在官方测试标记的1068段上分别答对375、397、363段，即约35.1%、37.2%、34.0%。这个测试组的原文件已因前面的腕向方向实验打开过；对**这三支动作模型**是第一次按固定权重评价，却不是本书第一次见这批来源。尤其不能拿内部约60%替代它们在官方分组上的约37%。验证与测试差距可能有视频来源、场景和数据量等原因，本次没有足够的消融把差额精确归给任何一种；按视频编号切开的内部验证也不能保证原长素材完全不交叉。[三支逐轮训练与选择](../runs/c33_penn_action_15/train.json)和[动作测试结果](../results/c33_penn_action_test.json)保留了十五类的逐类差异。

“无序平均略胜时间卷积”只属于这套 Penn 类别、八帧抽法、小架构与训练预算。它不能推成“视频的时间顺序不重要”：方向配对题刚才已经提供了反例。Penn 的投球、跳跃等动作，某些单帧姿势与运动场景本来就带有类别线索；内部小数据又可能没给时间支足够稳定的梯度。若换成真正以方向区分标签的资料，结论可变。2017年 Something-Something 研究资料就刻意放入类似“向左推”和“向右推”的细粒动作；它的标签设计迫使研究者更认真检查时间证据，但它不是我们的训练资料，不能借其论文成绩给本机小网背书。([Something-Something，2017，原论文](https://openaccess.thecvf.com/content_ICCV_2017/papers/Goyal_The_Something_Something_ICCV_2017_paper.pdf))

<a id="thirtythird-learned-time"></a>
## 为什么2014年以后有这么多不同的“时间层”

当单张图卷积在大图像资料上取得可见效果，研究者需要决定：让网络自己从连续 RGB 帧找变化，还是先用已有光流估计把移动方向明确交给它？Simonyan与Zisserman在2014年的两流方案分开外观 RGB 与稠密光流，两支最后结合。它不是一句“网络自动懂时间”：光流支的输入已经包含另一个计算程序从多帧提取的运动。2015年的 C3D 则让卷积核跨**时间×高×宽**一个小体块共享，用学习的权重同时响应空间形状和短时变化；那个“3D”是数组三轴，不是证明它知道真实立体空间。([两流 CNN，2014，摘要/§1](https://www.robots.ox.ac.uk/~vgg/publications/2014/Simonyan14b/simonyan14b.pdf)；[C3D，2015，原论文页](https://openaccess.thecvf.com/content_iccv_2015/html/Tran_Learning_Spatiotemporal_Features_ICCV_2015_paper.html))

2017年 Carreira 与 Zisserman 建立更大的 Kinetics 动作资料并研究把已有图像滤波器“膨胀”到时间维的 I3D。可用的视频资料规模和图像预训练同时改变了实验条件，不能把进步只归给某个卷积核多了一轴；而 Something-Something 则让人看到，动作名若不依赖方向，系统可能靠静态线索得到漂亮数字。再往后，2021年的 TimeSformer 用时空位置之间的注意力读取替代只在固定局部体块内读；2022年的 VideoMAE 把被遮住的视频块作为重建目标，让大量未逐段标动作的视频也提供学习信息。二者都需要说明**训练目标**：注意力可跨远帧不等于已学会物理规律；未写人工动作类也不等于没有由原视频供给的重建答案。([I3D/Kinetics，2017，摘要/引言](https://openaccess.thecvf.com/content_cvpr_2017/papers/Carreira_Quo_Vadis_Action_CVPR_2017_paper.pdf)；[TimeSformer，2021，摘要](https://proceedings.mlr.press/v139/bertasius21a/bertasius21a.pdf)；[VideoMAE，2022，摘要/方法入口](https://papers.neurips.cc/paper_files/paper/2022/file/416f9cb3276121c42eebb86352a4354a-Paper-Conference.pdf))

第十四章的循环状态和第十七章的注意力在这里各有入口：循环可以按顺序把新帧摘要并进 \(h_t\)，固定时长卷积只直接看邻近位置，注意力可以使较远帧互相读取。这是**可表示的信息路径**的比较，还要问计算成本、训练资料、目标和模型真的用没用它。在本章八帧实验里，我们没有训练大型循环或视频 Transformer，也没有把之前文本模型的权重冒充视频能力；读者已经能从真实小网络和明确失败看到为什么研究者需要不同的时间层。

<a id="thirtythird-future-task"></a>
## “看出动作”之外，再让画面真的往前走一步

动作分类的十五路分数不是一张未来图。现在仍用 Penn 的**真实三帧**，但把任务换成：已知 \(I_{t-5}\) 与 \(I_t\)，预测 \(I_{t+5}\)。人标右腕点只用于先筛出一批有可见运动的片段，模型的输入和目标都是原 RGB 像素；训练时既不给它“投球”这个类名，也不给未来关节或文字。把像素值除以255后，目标图每项在0到1之间。令网络输出 \(\hat I_{t+5}=f_\theta(I_{t-5},I_t)\)，我们选择每个批次、颜色、位置上平均平方偏差：

\[
L(\theta)=\frac{1}{NCHW}
\sum_{n=1}^{N}\sum_{c=1}^{C}\sum_{i=1}^{H}\sum_{j=1}^{W}
\bigl[f_\theta(I^{(n)}_{t-5},I^{(n)}_{t})_{cij}
-I^{(n)}_{t+5,cij}\bigr]^2.
\]

\(N\) 是这批多少个三帧组，\(C=3\) 为红绿蓝，\(H,W\) 为缩放补边后的90、160；分母明确告诉你报告的0.004一类数字是**每个 RGB 坐标**的平均误差，不是每张画面的平方和。网络先把两张彩色图拼成六通道，局部卷积压下去又上采样，最后预测对当前图的一项有限修正；这一结构让它容易先复制未变的背景。它从随机权重开始，训练程序里四行恰与上式衔接：

~~~python
past, current, future = batch(train, indexes, device, augment=True)
prediction = model(past, current)
loss = F.mse_loss(prediction, future)
optimizer.zero_grad(set_to_none=True)
loss.backward()
optimizer.step()
~~~

这是[本机训练程序](../code/c33_future_frame.py)的原代码片段；`batch` 把三张真实 RGB 帧按轴整理成 \((N,3,90,160)\) 的 Tensor，并可把三帧一起水平翻转。`future` 只在损失和评价里出现，不会作为 `model(past,current)` 的隐藏第三个输入。`loss.backward()` 从未来图与预测图的差算各层导数，`optimizer.step()` 才改权重；评估时不执行这两步。

在宣布网络“会预测”之前，先给一个强而免费的对照：根本不训练，直接把当前 \(I_t\) 当作 \(I_{t+5}\)。体育画面里背景常占多数像素，短间隔复制可能已经让全图平方误差很低。本机网络最初随机权重在内部验证片段上的每坐标误差约0.00694，甚至比复制当前的0.00650差。训练20轮，按验证全图均方误差选第18轮，315个验证片段上网络约0.00444，复制约0.00650。固定模型后，在官方测试组同一套筛选留下的1228个片段上再算，网络约0.00409、复制约0.00580；这批**来源**先前已被方向和动作任务使用，因此它是固定模型的跨视频复核，不是“全书从未看过来源”的又一次盲测。[训练报告](../runs/c33_future_frame_20/train.json)和[固定权重复核](../results/c33_future_official_split_recheck.json)分别给出轮次与分母。

还有一个容易误判的地方：背景占七成、九成时，全图误差可以随着背景抄得很准而下降，正在动的人却没有变清楚。我们另在**评价时**用真实未来与当前的 RGB 平均绝对差大于0.08标出有显著变化的像素；这个标记需要真实未来，只用来分层看错误，绝没有作为网络输入或训练标签。验证片段中这样的像素约7.4%，其每坐标误差网络约0.0477、复制约0.0839；官方测试来源的可用片段约7.0%，相应约0.0458、0.0790。网络并非只靠静止背景取胜，但这些数依赖我们自定的变化门槛，也没直接回答人的形状是否完整。

<a id="thirtythird-mean-future"></a>
## 为什么平均误差更小，眼里的投手却糊了

看[同一验证视频的五格实图与预测](../figures/c33_future_frame_validation_example.png)：左上是较早真帧，中上是当前真帧，右上是隔五个帧序号的真实未来；左下直接复制当前，中下是网络预测。网络在这张图上的均方误差约0.00277，复制约0.00371；人的身体轮廓却被画成半透明的重影。我们不能光看一张图就断言“全部模糊都由平方损失造成”：缩到90×160、网络容量、资料量、对齐误差和不确定的未来也都会影响。但平方损失确实给一种**向平均值走**的数学压力，值得独立算清。

设当前两帧给定后，真实下一像素 \(Y\) 仍可能因不同动作路线而有不同值；我们只能输出一个确定数 \(a\)。把条件平均记为 \(\mu=\mathbb E[Y\mid I_{t-5},I_t]\)。平方误差的条件期望可展开为

\[
\begin{aligned}
\mathbb E[(a-Y)^2\mid I_{t-5},I_t]
&=\mathbb E[((a-\mu)+(\mu-Y))^2\mid I_{t-5},I_t]\\
&=(a-\mu)^2+\mathbb E[(Y-\mu)^2\mid I_{t-5},I_t].
\end{aligned}
\]

交叉项为零，因为在给定这两帧后 \(\mathbb E[Y-\mu]=0\)；第二项不随我们选择的 \(a\) 变。于是这种**只能给一个数并以平方误差评价**的理想答案是条件平均 \(a=\mu\)。对 RGB 图的每个坐标同理。若一种未来手在左、一种未来手在右，两种完整图都有可能，平均图可能把两个位置各留下淡影；它在平方误差上可以合理，却不一定是一张现实会拍到的清晰图。这是教学上的条件推导，**不是**对本机重影各原因贡献的实测分解。

2015年预稿、2016年 ICLR 的 Mathieu、Couprie、LeCun 正面研究了像素预测变糊与细节目标的问题；2016年 Finn、Goodfellow、Levine 在机器人推物体的资料里又让模型额外看**拟执行的动作**，因为“人会怎样推”与“在没给动作时猜下一幅”是两件事。PredNet在2016年预稿、2017年论文以递推的预测偏差继续研究未来画面；Babaeizadeh等在2017年预稿、2018年论文显式给可能的未来加入随机变化，不再强迫一段历史只通向一张平均图。这里有几条平行的方案：改变画面评价、给更多将来条件、留状态、给随机变量。没有一条由我们的平方损失公式唯一推出，也不能拿 Penn 无控制动作的视频冒充 Finn 的机器人动作条件实验。([Mathieu等，2015/2016，摘要](https://arxiv.org/abs/1511.05440)；[Finn等，2016，摘要](https://proceedings.neurips.cc/paper/2016/hash/d9d4f495e875a2e075a1a4a6e1b9770f-Abstract.html)；[PredNet，2016/2017](https://arxiv.org/abs/1605.08104)；[随机未来，2017/2018](https://arxiv.org/abs/1710.11252))

<a id="thirtythird-rollout"></a>
## 一步接一步：输入开始来自模型自己以后

我们的训练目标一次只问隔五个帧序号的一张图。若从真实第19、24帧出发，网络给出第29帧的预测；接着把这张**预测**当作下一次的当前输入，再预测34、39、44帧，它看到的输入分布已经变了：真实视频在相应时刻是另一张图。这个差异不靠论文术语也能在[四步真图与生成图](../runs/c33_future_rollout_0005/four_step_real_vs_generated.png)看出，投手逐步淡成一团残影；同一验证视频每步对真实后续图的均方误差约0.00277、0.00385、0.00488、0.00546。[本地四步视频](../runs/c33_future_rollout_0005/generated_preview_4fps.mp4)以作者指定的每秒四张回放，不能拿它的播放秒数推原摄像时间。[回送程序](../code/c33_future_rollout.py)和[逐步结果](../runs/c33_future_rollout_0005/rollout.json)明确保存了第一步真实输入和之后的生成输入。四步误差单调上升只是这一例的观察，不是数学定理；但它足以证明：一次一帧 MSE 好于复制，仍不签收长视频里的人物连续、动作合理或物体始终存在。

<a id="thirtythird-generation-history"></a>
## 从预测一张未来图，走到生成一段新的视频

一个未来预测器要先见过去；生成整段新视频还要规定**从哪里开始**以及用户可以控制什么。2016年前后，研究者已同时走几条路：Vondrick等利用大量未逐段标注的视频研究场景动态与生成；2018年 MoCoGAN 把相对不变的画面内容和随时间变化的运动变量分开，使“同一主体，不同动作”成为可问的生成条件。2021年的 VideoGPT 先把视频压成离散时空符号，再按顺序预测符号；这是第十八、十九章离散序列训练思想的一条迁移，却另外需要学视频压缩器和时空位置。三者不能因都输出帧就写成同一种训练目标。([Vondrick等，2016，摘要](https://proceedings.neurips.cc/paper/2016/hash/04025959b191f8f9de3f924f0940515f-Abstract.html)；[MoCoGAN，2018，摘要](https://openaccess.thecvf.com/content_cvpr_2018/html/Tulyakov_MoCoGAN_Decomposing_Motion_CVPR_2018_paper.html)；[VideoGPT，2021，摘要](https://arxiv.org/abs/2104.10157))

第三十一章已从真实图像学过逐步加噪和去噪；若把原图换成整段 \(V=(I_1,\ldots,I_T)\)，也可以先构造带噪的视频 \(\tilde V_s=\sqrt{\bar\alpha_s}V+\sqrt{1-\bar\alpha_s}\,\varepsilon\)，再学由带噪视频和扩散步数 \(s\) 猜回噪声或干净视频。这里专用 \(s\) 表示**去噪步数**，避免与视频内部的帧序 \(t\) 混淆。即便损失在每个像素上可写，网络仍须跨时间交换信息、训练资料须包含完整片段，才能希望同一人物在邻帧保持身份。2022年的 Video Diffusion Models 在固定帧数片段上采用时空网络，并把较长输出另行组织；不能把第三十一章**只在单张服饰图训练**的权重改一下 Tensor 形状便当作本机视频生成。([Ho等，2022，NeurIPS论文摘要](https://papers.nips.cc/paper_files/paper/2022/file/39235c56aef13fb05a6adc95eb9d8d66-Paper-Conference.pdf))

到2024年，[Sora的公开技术报告](https://openai.com/index/video-generation-models-as-world-simulators/)描述了先把视频在空间和时间上压缩，再切成时空小块，让扩散 Transformer 在带文字条件的小块上训练；报告还说，高描述性的配对文字部分来自另外训练的画面描述器，短提示也可经语言模型扩写。可见文字条件的来历本身就是一项资料和模型工作，不能把“给视频网络一句话”当成免费接口。报告同时明说没有公开模型与实现细节，并列出玻璃破碎、物体状态和长片段一致性的失败；可见片段逼真，不能推出已经有准确通用的物理模拟器。2025年 [Sora 2 官方系统卡](https://openai.com/index/sora-2-system-card/)提出声画同步、文本控制等公开能力主张；[Veo 3.1 官方页面](https://deepmind.google/models/veo/)也展示原生声音，并报告在其指定文字、视频、声音提示上的人类并排偏好评价。那是发布者各自在有限条件下报告的能力与评价，既不等于我们本机小生成器达到同样效果，也不补全未公开的训练配方；Google自己的页面仍把自然一致的短语音列作继续改进的问题。这条发展线回答了“为何视频生成不只是许多独立图片”：跨帧身份、动作、声音和条件都要有自己的资料与评价，不会随画面网络的名字自动到来。

## 在电脑上换一个条件，再决定自己相信哪项证据

## 时间证据解决了什么，留下了什么

本章从一张重复出现的第36帧出发，已经分别回答三件事。画面要有另一时刻才能在我们构造的方向题中分开左右；光流式在单点仍只给一条约束，局部跟踪通过另加相近位移假设才可工作；整段动作识别与预测未来帧使用不同标签和损失，哪一项成绩也不能替另一项签收。本机两帧小网在筛选后的方向题拿到74.1%，三个原动作分类器在官方组外仅约34%—37%，确定性未来帧网络虽比复制少了像素误差，滚动时仍丢掉投手。我们不靠“视频模型”这个总名抹平这些真实差别。

还有一个更深的未解问题。图像里一个点的横坐标变化，不只取决于它在地面上怎样走。先做最简单的几何假设：相机只有一个让光线通过的投影中心，前方三维点沿着连接中心的直线落到平面图像上；这样的模型叫**针孔相机**。设相机暂时不动，三维点相对它的横、纵、深度坐标是 \((X,Y,Z)\)，投影中心到成像平面的尺度为焦距 \(f\)，画面中心横坐标为 \(c_x\)。相似三角形便给出图像横坐标 \(x=fX/Z+c_x\)。同样的 \(x\) 可以来自较远处较大的 \(X\)，也可以来自近处较小的 \(X\)；相机再移动，歧义更多。眼前的 RGB 帧、二维腕点和亮度流没有自动告诉我们 \(Z\) 或相机姿态。下一章就从这条缺失的关系出发，建立相机、多视角、三维重建与可编辑表示；它不是本章还欠着的某个方向分数说明，而是视频留下的另一个对象。

## 读完后自己回答

1. 用开头同一第36帧的两对输入，写出为什么只读最后一帧的确定性函数，在这**一道配对任务**上必得50%；再举一种可能凭单帧姿势就容易猜对的原 Penn 动作，说明两个结论并不冲突。
2. 从 \(I(x+u\Delta t,y+v\Delta t,t+\Delta t)\approx I(x,y,t)\) 展开得到哪条式子？一条竖直边为什么不能单点确定上下位移？局部共同位移、全图平滑各自增加了什么假设？
3. 八帧无序平均中交换第一与第八帧，最后特征为什么不变？有序时间卷积是否必然给不同结果？若内部验证无序平均约60.5%、官方组外约37.2%，哪一个可以作为现行组外动作成绩？
4. 已知当前两帧时，若真实未来图有两种位置都可能，平方误差的最佳确定输出为何是平均图？这个结论能不能单独解释本机投手残影的全部原因？
5. 你有两帧像素位移和人工右腕二维坐标，却没有相机参数、深度或可信帧率。哪些量现在能报告，哪些不能？若额外得到一台标定相机和第二个视角，下一章最先应补哪一条几何关系？

<summary>核对思路</summary>

1. 每个中心的末帧文件相同，却各有一次左和一次右标签；同一个函数值不可能同时对两项，所以每对一中一错。Penn 的某些球拍、运动场背景或明显姿势可能让单张图在其原整段类别任务里有用；那是不同标签与资料分布。
2. 一阶泰勒展开得 \(I_xu+I_yv+I_t\approx0\)。竖边几乎没有垂直亮度梯度 \(I_y\)，这一式对 \(v\) 无区分力。局部法近似一个小窗内共同平移，且要有两个方向的亮度梯度；全图法另规定流场大体平滑，两者都不是单点亮度恒定的必然结果。
3. 向量加法交换后总和不变；有序网络有表达不同输出的能力，但权重可能学成近似不敏感，故不是必然。按固定模型在官方组别上的397/1068即约37.2%报告；内部60.5%只用于选择并帮助诊断落差。
4. 将 \(Y\) 减去其条件均值，展开 \((a-Y)^2\) 后交叉项为零，只有 \((a-\mu)^2\) 随 \(a\) 改变；所以最优确定值是 \(\mu\)。本机残影还可能由分辨率、对齐、样本量和结构造成，不能从定理给它们分配比例。
5. 可报告图像坐标上的像素差、帧序间隔、在已说明条件下的方向或误差；不能把它们换算真实秒数、米每秒、独立物体三维运动。多视角先需知道每台相机怎样把三维点投到图像以及视角间的对应，之后才有条件尝试恢复深度。
